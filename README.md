# MacMonitor

2015 Intel iMac과 macOS 12 Monterey를 대상으로 하는 개인용 원격 카메라입니다. **핵심 기능은 원할 때 휴대폰으로 보는 원격 실시간 영상입니다.** 평소에는 카메라를 끄고 대기하다가, 로그인한 시청자가 실시간 화면을 열 때만 켭니다. 녹화는 웹에서 시간을 골라 시작하는 원격 녹화 하나입니다. 자세한 동작은 [원격 실시간 영상](docs/FEATURE_7_REMOTE_LIVE_ON_DEMAND.md)을 참고하세요.

2026-11-08 추가: 텔레그램 봇에게 `카메라`라고 보내면 카메라가 켜지고 링크가 옵니다. 슬림 모드를 켜면 Mac이 평소에 잠들어 있다가 10분마다 깨어나 요청을 확인합니다. 웹의 실시간 화면에서 시간(1~24시간)을 골라 시작하는 원격 녹화는 접속을 끊어도 그 시각까지 이어지고, 용량은 기존 최대 녹화 용량으로 제한합니다. 요일·시간표 예약 녹화는 같은 날 저녁 사용자의 결정으로 제거했습니다. 설계와 Mac에서 확인할 항목은 [슬림 모드·텔레그램·원격 녹화](docs/FEATURE_8_SLIM_MODE_CHAT_SCHEDULE.md)에 있습니다. Swift 소스는 2026-11-08 대상 iMac에서 처음 컴파일되었고, 그때 실패한 테스트 1개는 테스트 쪽 결함이라 고쳤습니다. 같은 날 저녁 소리(실시간·녹화)와 웹 녹화 삭제를 더했으며([기능 9](docs/FEATURE_9_AUDIO_AND_DELETE.md)), 그 Swift 변경은 다시 컴파일 전입니다. 같은 날 밤 움직임 감지 녹화(메뉴·설정·감지기·병합기)를 제거해 남은 모드는 꺼짐·실시간·원격 녹화 셋입니다. 앱 실행과 기능 동작은 아직 Mac에서 확인하지 않았습니다. 2026-11-09 "화면이 꺼져도 잠들지 않고, 재운 뒤 텔레그램 답이 없다"는 보고를 코드로 조사해 두 원인(잠들기 전 입력을 깬 뒤에도 사람이 있는 것으로 셈, 텔레그램 `카메라` 시험이 카메라를 10분 켜 둠)을 고치고, 확인 창을 90초 `PreventSystemSleep`으로 바꾸고, 왜 잠들지 않는지를 `상태` 답장·웹·Console에 보이게 했습니다([기능 8 문서 §3.5](docs/FEATURE_8_SLIM_MODE_CHAT_SCHEDULE.md)).

메뉴 막대 앱이 카메라와 마이크를 소유하고, 하나의 인코딩 결과를 MediaMTX WebRTC와 (원격 녹화 중이면) 로컬 MP4 파일에 함께 사용합니다.

## 구현된 수직 경로

```text
AVFoundation 720p/15fps + 마이크 48kHz
  └─ FFmpeg h264_videotoolbox 단일 인코딩 (+ Opus / AAC)
       ├─ 원격 녹화 중: 10분 MP4 → Recordings (기간·용량·여유 보관, 보호 제외)
       └─ loopback RTSP → MediaMTX → WebRTC

휴대폰 HTTPS
  → Go 인증 게이트웨이
      ├─ 로그인/세션/CSRF/시도 제한
      ├─ 인증된 MediaMTX WebRTC 프록시
      └─ 인증된 녹화 목록/Range 재생
```

구현 항목:

- 원격 시청 대기: 접속하면 카메라가 켜지고 시청을 멈추면 약 20초 뒤 꺼짐, 실시간만 볼 때는 녹화 파일 없음, 대기 중 화면은 꺼지고 시스템은 깨어 있음
- 텔레그램 명령: 허용한 채팅에서 `카메라`를 보내면 10분 동안 카메라를 켜고 링크를 답장, `그만`으로 끄기, `상태`로 앱 상태 확인, `진단`으로 잠자기·깨어남 기록과 카메라 상태를 받기 (`scripts/configure-telegram.sh`)
- 슬림 모드: 시청자·녹화가 없고 입력이 5분 없으면(잠들었다 깬 뒤에는 깬 뒤 입력이 없으면) Mac이 잠들고, 설정한 간격(기본 10분)마다 약 1분 30초 깨어나 텔레그램 요청 확인 (`scripts/enable-slim-mode.sh`로 깨우기 예약 권한 설치)
- 원격 녹화: 웹에서 1~24시간을 골라 시작, 접속을 끊어도 그 시각까지 감지 없이 10분 단위 연속 저장, 기존 보관 기간·최대 용량·최소 여유 규칙 적용
- 소리: 마이크 소리를 실시간(Opus)과 녹화 파일(AAC)에 함께 넣음, 설정에서 끌 수 있음, 권한·인코더가 없으면 소리 없이 계속 동작하고 이유 표시 ([기능 9 문서](docs/FEATURE_9_AUDIO_AND_DELETE.md))
- 웹에서 녹화 삭제: 카드의 `삭제` 버튼, 확인 창, 보호된 녹화는 보호 해제 뒤에만
- macOS 12용 메뉴 막대 앱과 설정 창
- 앱 실행 비밀번호 (최초 설정, 키체인에 PBKDF2 검증값 저장)
- 사용자 선택형 로그인 자동 실행 및 비밀번호 확인 후 원격 대기
- 매일 예약 잠자기·깨우기와 기존 앱 세션의 녹화 재개
- 카메라 권한·장치 선택, 720p/15fps NV12 캡처, 프레임 하트비트
- 화면 절전은 허용하고 시스템 자동 유휴 잠자기만 방지
- VideoToolbox H.264 단일 인코딩과 RTSP/MP4 tee
- 기간·용량·최소 여유 공간 보관 정책
- 중요 녹화 보호/해제·보호 항목 검색, 앱 재실행 후 유지, 자동 정리와 보호 저장 간 공유 잠금·공간 부족 경고
- 진단 로그별 10MB 제한과 최근 3세대 자동 회전
- MediaMTX의 RTSP/HTTP listener를 loopback으로 제한
- 고정 UDP/TCP 8189 WebRTC ICE 포트
- PBKDF2-SHA256 비밀번호, Secure/HttpOnly/SameSite 세션, CSRF 및 로그인 제한
- HTTPS 뒤의 모바일 실시간 화면과 녹화 재생 화면
- 원격 자동·원본·480p 표준·360p 절약 화질, 시청 시에만 축소 인코딩 및 수신 상태 기반 재연결 전환 (로컬 녹화 설정 유지)
- 녹화 시작 날짜 검색, 50개씩 페이지 이동, 지연 로딩 썸네일과 인증된 원본 MP4 다운로드
- 녹화 중지·화면 전용 휴식 중에도 로그인과 과거 녹화 목록·재생 유지 (인증된 앱 실행 및 Mac이 깨어 있는 동안)
- 실제 프레임 수신/FPS·최근 녹화·디스크 여유·소리 상태판, 감시 중 프레임 정지 시 기존 절차로 복구
- 카메라 세션·FFmpeg·MediaMTX 비정상 종료 감지, 2/5/15초 간격의 최대 3회 자동 복구 및 안전한 감시 종료. HTTPS 웹 서버는 감시와 독립적으로 10초 주기로 재시도
- 공식 체크섬을 검증하는 MediaMTX 설치 스크립트
- Swift 상태/보관/소리 정렬 테스트와 Go 게이트웨이 테스트

## Mac에서 준비하고 실행

Mac으로 옮길 최신 소스 ZIP은 [releases](releases/)에 있습니다. 날짜·시각이 가장 늦은 묶음이 2026-10-27 병합본입니다. 그 이전 묶음에는 기능 1~6과 2026-10-23 빌드 수정 중 한쪽이 빠져 있으니 받지 마세요. 초기 오류 수정은 [재점검 기록](docs/RECHECK_2026-10-20.md), 기능 5·6의 감지 표본·뒤로가기 복원·특수문자 실행 경로 수정은 [후속 리뷰 수정 기록](docs/REVIEW_FIXES_2026-10-20.md), 대상 iMac 첫 빌드 보고에 따른 빌드 도구·Xcode 14.2 컴파일 수정은 [2026-10-23 재점검 기록](docs/RECHECK_2026-10-23.md)에 정리했습니다. 병합 소스의 Swift 빌드와 실제 카메라·전원 동작은 검증 전입니다.

전체 순서는 [docs/SETUP_MAC.md](docs/SETUP_MAC.md)에 있습니다. 요약하면 다음과 같습니다.

명령어 없이 실행하려면 Finder에서 저장소 루트의 `Build MacMonitor.command`를 더블클릭합니다. 필요한 MediaMTX 준비, 테스트, Thread Sanitizer, 앱 빌드, 실행 전 진단과 앱 실행까지 이어서 처리하며 전체 출력은 `dist/build-날짜-시간.log`에 저장합니다. 빌드가 끝나면 앱을 열기 전에 원격 웹(설정이 없을 때만, 텔레그램 봇이 이 웹 서버 안에서 돕니다), 텔레그램 봇 토큰(설정이 없으면 입력, 있으면 Return으로 유지하거나 새 토큰으로 교체)과 슬림 모드 깨우기 권한(이미 있으면 건너뜀)을 같은 창에서 설정합니다. 토큰은 입력해도 화면과 로그에 표시되지 않습니다. 같은 Wi-Fi의 휴대폰에서 접속하려면 빌드 뒤 `Setup Remote Web.command`를 더블클릭합니다. 인증서와 웹 설정을 만들고 열 주소를 보여 주며, Mac 주소가 바뀌었을 때만 다시 실행하면 됩니다. 밖(휴대폰 데이터망)에서는 공유기 포트포워딩만 하고 `https://공인IP:8443`을 열면 되며, 공인 IP를 설정에 적을 필요는 없습니다. Tailscale 주소도 됩니다(`docs/SETUP_MAC.md` 4절).

터미널에서 개별 실행하려면 다음 명령을 사용합니다.

```bash
chmod +x scripts/*.sh
./scripts/fetch-mediamtx.sh
./scripts/build-app.sh
./scripts/diagnose.sh
open dist/MacMonitor.app
```

빌드에는 Xcode 14.2, Go 1.26.x, 앱이 실제로 찾을 수 있는 경로의 FFmpeg가 필요합니다. Command Line Tools만 선택된 상태로는 빌드되지 않으므로 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`로 Xcode를 활성 개발자 경로로 지정해야 합니다. Monterey에서 Homebrew bottle이 없을 때의 FFmpeg 설치 절차는 [docs/SETUP_MAC.md](docs/SETUP_MAC.md)에 있습니다. 빌드 스크립트는 도구와 버전을 먼저 검사하고 Swift·Go 테스트 후 Intel `x86_64` 앱을 임시 번들에 조립합니다. 아키텍처·plist·privacy manifest·서명을 모두 확인한 번들만 `dist/MacMonitor.app`으로 교체하므로 패키징 실패 시 기존 앱은 유지됩니다. `MACMONITOR_TSAN=1 ./scripts/build-app.sh`로 Thread Sanitizer 테스트까지 포함할 수 있습니다.

`diagnose.sh`는 앱 실행 전에 VideoToolbox 실제 1프레임 인코딩, 번들 아키텍처와 서명, MediaMTX 버전과 생성 설정, 앱 데이터 권한을 확인합니다. 게이트웨이가 설정되어 있으면 JSON, 인증서/개인키 짝, 인증서 유효기간·호스트명, 녹화 경로도 서버를 열지 않고 검사합니다. 실패 항목이 하나라도 있으면 종료 코드 1을 반환합니다.

메뉴 막대의 `설정…`에 있는 외부 WebRTC 호스트는 비워 둬도 됩니다(게이트웨이가 휴대폰이 연 주소를 영상 연결에 더합니다). HTTPS까지 설정하면 앱이 카메라 권한을 묻습니다. 승인해 두면 이후 원격 접속 때 카메라가 저절로 켜집니다. 움직임 녹화를 쓰려면 메뉴의 `움직임 녹화 시작`을 누릅니다.

텔레그램 봇과 슬림 모드 깨우기 권한은 `Build MacMonitor.command`가 빌드 끝에 묻습니다. 따로 하려면 `./scripts/configure-telegram.sh --ask`(토큰을 숨겨 입력)나 `./scripts/configure-telegram.sh <봇 토큰>`을 실행하고 안내대로 봇에게 메시지를 한 번 보내고, `./scripts/enable-slim-mode.sh`로 깨우기 예약 권한을 넣습니다. 그 뒤 설정에서 `슬림 모드`를 켭니다. 두 절차는 [docs/SETUP_MAC.md](docs/SETUP_MAC.md) 7~9절에 있습니다.

최초 실행에는 12자 이상의 앱 비밀번호를 설정합니다. 이후 앱 실행마다 입력해야 하며 웹 접속 비밀번호와는 별개입니다. 비밀번호는 앱 실행을 잠그는 기능이며 MP4 파일을 암호화하지는 않습니다.

HTTPS를 설정해 두면 앱 비밀번호 확인 후 웹 서버가 카메라와 별도로 시작됩니다. 로그인해서 실시간 화면을 열면 `카메라 켜는 중…` 뒤에 영상이 나옵니다. 메뉴의 `원격 시청 대기`를 끄면 원격에서 카메라를 켤 수 없고, 저장된 녹화만 볼 수 있습니다. 앱 종료·로그아웃·시스템 잠자기 중에는 접속할 수 없습니다. 대기 중에는 시스템 유휴 잠자기를 막습니다. 자세한 동작은 [원격 실시간 영상](docs/FEATURE_7_REMOTE_LIVE_ON_DEMAND.md)과 [원격 녹화 접근 분리](docs/FEATURE_1_ARCHIVE_ACCESS.md)를 참고하세요.

원격 상태판은 약 5초마다 실제 카메라 프레임 도착·FPS·최근 사건 완료·디스크 여유를 표시합니다. 앱 상태가 오래되면 정상 표시를 하지 않습니다. 감시 중 첫 영상 대기 15초 또는 이후 프레임 단절 10초를 넘으면 기존 제한된 자동 복구로 연결하며, 의도적인 중지·휴식에는 작동하지 않습니다. 자세한 검증 범위는 [상태판과 정지 복구](docs/FEATURE_2_MONITORING_HEALTH.md)에 있습니다.

녹화 탭에서는 접속 기기의 현지 날짜로 시작 시각을 검색하고 50개씩 이동합니다. 작은 썸네일만 지연 로딩하며 재생을 누르기 전에는 MP4를 미리 받지 않습니다. 원본 다운로드는 로그인 세션과 Range를 유지합니다. 썸네일은 FFmpeg로 한 번에 하나씩 제한 시간 안에서 만들며 실패해도 재생/다운로드 경로는 유지합니다. [녹화 탐색 안내와 Mac 검사](docs/FEATURE_3_RECORDING_BROWSER.md)를 참고하세요.

중요 녹화는 카드에서 보호하면 기간·용량·디스크 여유 정리에서 제외되며 앱 재실행 뒤에도 유지됩니다. 보호된 파일 때문에 공간이 부족하면 보호를 풀어 삭제하지 않고 경고합니다. 해제 후에는 다음 정리에서 삭제될 수 있으므로 먼저 백업하세요. [보호 설정·공유 잠금·검증 범위](docs/FEATURE_4_RECORDING_PROTECTION.md)를 참고하세요.

원격 화질은 실시간 탭에서 브라우저별로 선택합니다. 자동 모드는 표준으로 시작해 수신 통계에 따라 전환하며 전환 때 잠깐 재연결됩니다. 표준·절약에 필요한 추가 인코더는 시청할 때만 만들고 녹화는 그대로 유지합니다. [화질 프로필과 실제 Mac 검증](docs/FEATURE_6_REMOTE_QUALITY.md)을 참고하세요. 현재 캡처가 4K로 바뀐 것은 아니며 실제 회선에서의 무끊김을 보장하지 않습니다.

`매일 예약 사용`에서 예를 들어 23:00 휴식 시작, 06:00 감시 재개를 지정하고 두 모드 중 선택합니다.

- **시스템 잠자기 → 깨운 직후 화면 끄기**: 관리자 인증 후 Mac 전체 전원 예약을 등록합니다. 1분 전 감시를 정리하고 예약 깨우기 후 화면 끄기를 한 번 요청하며 감시를 재개합니다. 화면이 잠깐 켜지는 현상까지 막지는 못합니다.
- **시스템 유지 · 화면만 끄기**: 시스템 유휴 잠자기를 막고 휴식 시작에 화면을 끕니다. 휴식 중 카메라·녹화는 중단하고 재개 시각에 다시 동작합니다. 화면을 켜는 명령은 보내지 않습니다. 최초 설정에는 관리자 인증이 필요 없지만 기존 시스템 잠자기 예약에서 전환하면 예약 해제 인증이 필요합니다.

두 모드 모두 앱을 실행·인증한 상태로 두어야 합니다. 키보드·마우스 사용은 우선하며 화면을 반복해서 끄지 않습니다. 수동 잠자기·덮개 닫기·전원 차단까지 방지하지는 않습니다. 로그아웃/재부팅 후에는 앱 비밀번호를 다시 입력해야 합니다. 앱 종료 시 화면 전용 모드의 잠자기 방지는 해제되지만 시스템 전원 예약은 남으므로 설정에서 예약을 끄고 저장해 해제하세요.

## 애플리케이션 데이터

```text
~/Library/Application Support/MacMonitor/
├── config.json
├── gateway.json
├── Diagnostics/
├── Recordings/
├── Runtime/
└── Spool/
```

앱은 `Spool`과 `Recordings`만 보관 정책에 따라 정리합니다. 다른 디렉터리는 삭제 대상으로 삼지 않습니다.

## 제거

압축을 푼 폴더의 `Uninstall MacMonitor.command`를 더블클릭하거나 `./scripts/uninstall.sh`를 실행합니다. 실행 중인 앱과 도우미를 멈춘 뒤 로그인 자동 실행 등록, 키체인의 앱 비밀번호, 위 애플리케이션 데이터, 빌드된 `dist/MacMonitor.app`, 카메라 권한 기록을 지웁니다. **녹화 파일은 남깁니다.** 녹화까지 지우려면 `./scripts/uninstall.sh --recordings`를 실행하세요.

Mac 전체에 걸리는 반복 전원 예약(모드 1)은 자동으로 해제하지 않습니다. 앱이 넣은 것인지 사용자가 직접 설정한 것인지 구분할 수 없기 때문에, 현재 예약을 보여주고 따로 한 번 더 확인한 뒤에만 `sudo pmset repeat cancel`을 실행합니다. 슬림 모드의 sudoers 규칙(`/etc/sudoers.d/macmonitor`)과 앱이 넣은 깨우기 예약도 같은 방식으로 보여 준 뒤 따로 확인받아 지웁니다. 소스 폴더 자체는 지우지 않으므로 끝난 뒤 직접 휴지통으로 옮기세요.

## 아직 실제 Mac 검증이 필요한 항목

이 Windows 환경에서는 Swift/macOS 프레임워크를 컴파일하거나 카메라·VideoToolbox·전원 동작을 실행할 수 없습니다. MediaMTX 1.21.1 설정 기동, Go 테스트 및 macOS/amd64 교차 빌드는 여기서 확인했지만 아래 항목은 대상 iMac에서 판정해야 합니다.

2026-10-23 대상 iMac 보고에서 Swift 테스트·Thread Sanitizer·릴리스 빌드가 통과했습니다(기능 1~6이 없는 76개 파일 소스). 2026-11-07에는 기능 1~6을 포함한 병합 소스가 같은 iMac에서 컴파일됐고 Swift 테스트 76개 중 73개가 통과했습니다. 실패 3개는 Darwin Foundation 동작을 잘못 가정한 테스트 결함이라 테스트를 고쳤으며([2026-11-07 기록](docs/RECHECK_2026-11-07.md)), 그 뒤 단계는 다음 빌드에서 확인합니다.

- 2026-11-07 이후 수정한 Swift 소스의 컴파일과 테스트 (원격 시청 대기, 슬림 모드, 원격 녹화 포함)
- 슬림 모드: `pmset schedule wake`의 날짜 형식과 실제 깨어남, 예약 깨우기가 화면을 켜는지, `pmset sleepnow`의 권한, 깨어난 뒤 60초 안의 네트워크 복구
- 텔레그램 실제 API 연동과 원격 녹화 10분 세그먼트의 파일 완성·재생
- 소리: 마이크 권한 창, FFmpeg가 두 입력·두 오디오 인코더 tee 명령을 받아들이는지, 영상·소리 동기화와 1시간 뒤 유지, WebRTC 소리 재생
- 화면 꺼짐·잠금 상태에서 원격 요청으로 카메라를 새로 시작하는 동작
- 카메라 권한과 실제 720p/15fps 포맷
- `h264_videotoolbox` 인코더 및 FFmpeg tee 동작
- 화면 꺼짐·잠금 상태의 프레임/녹화 지속
- 휴대폰 데이터망 WebRTC와 공유기 NAT 후보
- TLS 인증서, DDNS, 포트포워딩
- 장시간 CPU·메모리·발열·디스크 사용
- 인코딩된 내용 길이가 벽시계 시간과 일치하는지 (세그먼트 간격 5초 유지)

검증 절차는 [docs/MAC_VALIDATION.md](docs/MAC_VALIDATION.md), 네트워크 경계는 [docs/NETWORK_SECURITY.md](docs/NETWORK_SECURITY.md)를 따릅니다. 2026-10-07 신뢰성 수정의 변경 내용과 미검증 범위는 [docs/RELIABILITY_FIXES.md](docs/RELIABILITY_FIXES.md), 2026-10-23 빌드 도구·컴파일 수정은 [docs/RECHECK_2026-10-23.md](docs/RECHECK_2026-10-23.md)에 있습니다.
