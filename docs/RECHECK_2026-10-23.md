# 2026-10-23 빌드 도구 확인과 Xcode 14.2 컴파일 수정

대상 iMac의 첫 원클릭 빌드 보고를 바탕으로 수정했습니다. Go 설치 후 `xcodebuild`가 `tool 'xcodebuild' requires Xcode` 오류로 멈췄고, Xcode 14.2 선택 후에는 FFmpeg 확인에서, FFmpeg 설치 후에는 첫 Swift 컴파일에서, 컴파일 수정 후에는 릴리스 실행 파일의 아키텍처 확인에서 멈췄습니다.

## 수정한 문제

- Xcode 선택: Command Line Tools만 선택된 상태에서는 `/usr/bin/xcodebuild`가 존재해 명령 확인을 통과한 뒤 xcode-select 오류로 끝났습니다. `build-app.sh`가 버전 확인 전에 `xcode-select -p`가 `.app/Contents/Developer`인지 검사하고, 아니면 Xcode 14.2 설치와 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` 실행을 안내합니다.
- Swift 버전 출력: Xcode 14의 swift-driver는 `swift-driver version: 1.62.15 `를 줄바꿈 없이 stderr로, `Apple Swift version 5.7.2 (...)`를 stdout으로 씁니다. 기존 파서는 stdout만 읽어 버전 확인은 통과했지만 stderr 조각이 다음 오류 메시지 앞에 붙어 출력됐습니다(대상 iMac 로그에서 확인). `build-app.sh`와 `diagnose.sh`는 두 출력을 함께 읽고 `Swift version` 다음 값을 사용하므로 출력 형식과 관계없이 같은 버전을 얻고 조각을 남기지 않습니다.
- FFmpeg: Homebrew가 Monterey를 Tier 3로 낮춰 bottle이 거의 없으므로 `SETUP_MAC.md`와 `MAC_TEST_START_HERE.txt`에 Intel용 정적 FFmpeg를 `/usr/local/bin`에 설치하는 절차를 추가했습니다. 빌드 오류 메시지도 이 문서를 가리킵니다.
- 문서: Xcode 14.2 다운로드 위치와 선택 명령을 추가했습니다.
- Swift 컴파일: `AVCaptureSession.runtimeErrorNotification`은 macOS 14 SDK(Xcode 15)에서 생긴 이름이라 Xcode 14.2의 macOS 13.1 SDK에서 `type 'AVCaptureSession' has no member` 오류가 났습니다. 같은 알림의 기존 이름 `.AVCaptureSessionRuntimeError`를 사용합니다.
- 컴파일 재점검: 모든 Swift 소스와 테스트를 macOS 13.1 SDK / Swift 5.7 기준으로 다시 읽었습니다. 다른 SDK 신규 API나 Swift 5.8 이후 문법은 찾지 못했습니다. 지역 상수가 같은 이름의 메서드·프로퍼티를 가리던 두 곳(설정 창 `save` 버튼, 녹화 정리 `timer`)은 컴파일러 버전에 따라 해석이 달라질 수 있어 이름을 바꿨습니다.
- lipo 인자 순서: `lipo -verify_arch x86_64 <파일>`은 `-verify_arch` 뒤의 파일 경로까지 아키텍처 이름으로 읽어 `unknown architecture specification flag`로 실패했습니다. `build-app.sh`의 두 곳과 `diagnose.sh`가 `lipo <파일> -verify_arch x86_64` 순서를 사용합니다. 대상 iMac에서 이 단계 전의 Swift 테스트, Thread Sanitizer 테스트와 릴리스 빌드는 통과했습니다.

## 실행한 검사

- `scripts/test-script-regressions.sh`: 두 스크립트의 실제 Swift 버전 파이프라인을 Xcode 14.2 출력(stderr 분리형과 한 줄형)으로 실행해 버전이 5.7.2이고 다른 출력이 남지 않는지 확인합니다. 이전 스크립트는 stderr 조각이 남아 실패하고 수정본은 통과합니다.
- `scripts/test-script-regressions.sh`: `lipo -verify_arch`가 입력 파일보다 앞에 오면 실패하는 검사를 추가했습니다. 이전 스크립트에서는 실패하고 수정본은 통과합니다.
- `bash -n scripts/build-app.sh scripts/diagnose.sh`
- 게이트웨이: Linux에서 `go test ./...` 통과, `GOOS=darwin GOARCH=amd64`로 `go vet`과 x86_64 Mach-O 빌드 확인.
- Swift 수정은 이 환경(Linux)에서 컴파일할 수 없어 소스 검토만 했습니다.

앱 번들 조립·서명, 실행 전 진단과 실제 실행은 대상 Mac에서 아직 확인해야 합니다.
