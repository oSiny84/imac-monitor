# 실제 iMac 검증 — 캡처·복구·녹화

이 절차는 첫 번째 위험 항목인 **화면 꺼짐·잠금 중 카메라 지속성**과 함께 자동 복구, 사건 녹화, 로그인 자동 시작까지 대상 Mac에서 판정합니다.

## 준비

1. iMac을 macOS Monterey 12.5 이상으로 업데이트하고 Xcode 14.2 Command Line Tools를 선택합니다.
2. `MACMONITOR_TSAN=1 ./scripts/build-app.sh`를 실행해 일반 테스트, Thread Sanitizer와 앱 빌드를 마칩니다.
3. `./scripts/diagnose.sh`를 실행해 `[FAIL]`이 0개인지 확인합니다. 최초 감시 전 생성 설정이 없다는 `[WARN]`은 허용합니다.
4. `open dist/MacMonitor.app`으로 실행하고 메뉴 막대에서 `움직임 녹화 시작`을 누릅니다.
5. 카메라 권한을 승인하고 초록색 카메라 표시등이 켜지는지 확인합니다. 표시등은 정상이며 숨기지 않습니다.
6. 다음 명령에서 `PreventUserIdleSystemSleep` assertion의 소유자가 MacMonitor인지 기록합니다.

```bash
pmset -g assertions
```

## A. 디스플레이 꺼짐

1. 감시를 시작한 시각을 기록합니다.
2. 설정된 디스플레이 절전 시간이 지나 화면이 자연스럽게 꺼지게 둡니다. 키 입력이나 원격 명령으로 강제하지 않습니다.
3. 최소 2분 기다립니다.
4. 로컬 키보드 또는 마우스로 화면을 깨웁니다.
5. 로그 끝부분에 화면이 꺼져 있던 구간 동안 약 10초 간격의 `frame_heartbeat`가 이어졌는지 확인합니다.

```bash
tail -n 30 "$HOME/Library/Application Support/MacMonitor/Diagnostics/capture-probe.jsonl"
```

## B. 세션 잠금

1. 감시 실행 상태에서 Apple 메뉴의 화면 잠금을 사용합니다.
2. 디스플레이가 꺼진 뒤 최소 2분 기다립니다.
3. 로컬에서 잠금을 해제합니다.
4. 같은 로그에서 잠금 구간의 `timestamp`, `uptimeSeconds`, `totalFrames`가 중단 없이 증가했는지 확인합니다.

## C. 종료 복구

1. 메뉴에서 `움직임 녹화 중지`를 선택합니다.
2. 카메라 표시등이 꺼지고 `capture_stopped`가 기록되는지 확인합니다.
3. `pmset -g assertions`에서 MacMonitor의 assertion이 사라졌는지 확인합니다.
4. 평소의 시스템 자동 잠자기와 디스플레이 절전이 다시 동작하는지 확인합니다.

## D. 비정상 종료 자동 복구

1. 감시 중 Activity Monitor에서 `mediamtx` 프로세스만 종료합니다.
2. 메뉴 상태가 `자동 복구 1/3`으로 바뀌고 약 2초 후 다시 `감시 중`이 되는지 확인합니다.
3. 한 번 더 종료해 5초 간격의 두 번째 복구를 확인합니다. 세 번째 간격은 15초이며 이후에도 계속 실패하면 오류 상태로 멈춰 무한 재시작하지 않아야 합니다.
4. 복구 대기 중 `움직임 녹화 중지`를 눌러 예약된 재시작이 취소되는지 확인합니다.
5. 복구 예산이 세션 수명 상한이 아니라 플래핑 가드임을 확인합니다. 예산을 모두 소진해 오류 상태가 되기 전에, 복구 직후 상태로 5분 이상 연속 가동하고 다시 `mediamtx`를 종료합니다. 상태가 `자동 복구 1/3`부터 다시 시작해야 합니다. 2/3이나 3/3으로 올라가면 리셋이 동작하지 않는 것입니다.

## E. 사건별 녹화 파일

1. 감시 중 카메라 앞에서 5초 정도 움직인 뒤 정지합니다.
2. 마지막 움직임부터 `설정된 사전 보존 + 사후 보존 + 10초`를 기다립니다. 앞뒤 30초이면 70초, 앞뒤 1분이면 130초를 기다립니다.
3. `Recordings`에 `motion-*.mp4` 한 개가 생성되고 감지 전·후 구간까지 재생되는지 확인합니다.
4. 사후 구간이 끝까지 들어갔는지 확인합니다. `Recordings`에 사건에 속하지 못한 `segment-*.mp4`가 남아 있으면 안 됩니다. 병합이 꼬리 세그먼트보다 먼저 실행된 징후입니다.
5. 병합 오류가 발생했다면 `segment-*.mp4` 원본이 삭제되지 않고 모바일 목록에서 재생되는지 확인합니다.

## F. 로그인 자동 시작

1. 설정에서 `로그인 시 실행 (비밀번호 확인 후 원격 대기)`를 켜고 저장합니다.
2. `~/Library/LaunchAgents/local.macmonitor.app.plist`가 생성됐는지 확인합니다.
3. 로그아웃 후 다시 로그인해 앱 비밀번호 창이 표시되는지, 확인 전에는 웹 서버가 시작되지 않고 올바른 비밀번호를 넣은 뒤 원격 대기 상태가 되는지 확인합니다. 카메라는 시청자가 접속할 때까지 꺼져 있어야 합니다.
4. 앱 위치를 옮겼다면 자동 실행을 껐다가 새 위치의 앱에서 다시 켭니다.

## G. 인코딩 시간 드리프트

FFmpeg `rawvideo` 입력은 타임스탬프를 전달하지 못하므로 `-framerate 15`가 그대로 믿어집니다. 실제로 15fps가 들어가지 않으면 인코딩된 내용이 벽시계보다 짧아지고 오차가 누적됩니다. 녹화가 빠르게 재생되고, 세그먼트가 이름이 뜻하는 5초보다 긴 구간을 담아 보존 정책의 전후 구간 계산이 틀어지며, 실시간 영상이 점점 밀립니다. `ConstantRateFramePacer`가 이를 보정하는데, 실제 보정 여부는 이 절에서만 판정할 수 있습니다.

### G-1. 실제 캡처 프레임레이트

드리프트 압력이 존재하는지 먼저 확인합니다. 감시를 2분 이상 돌린 뒤 실행합니다.

```bash
grep frame_heartbeat "$HOME/Library/Application Support/MacMonitor/Diagnostics/capture-probe.jsonl" | tail -n 2 | awk '{ if (match($0, /"uptimeSeconds":[0-9.]+/)) { u = substr($0, RSTART+16, RLENGTH-16) } if (match($0, /"totalFrames":[0-9]+/)) { f = substr($0, RSTART+14, RLENGTH-14) } if (NR==1) { u0=u; f0=f } else { printf "capture %.2f fps over %.1f s\n", (f-f0)/(u-u0), u-u0 } }'
```

15에 가까우면 드리프트 압력이 없는 카메라입니다. 12~13이 나오면 보정 없이는 드리프트가 발생하는 조건이므로 G-2가 특히 중요합니다. 어느 쪽이든 측정값을 기록합니다.

### G-2. 세그먼트 벽시계 간격 (핵심 판정)

세그먼트 파일 이름은 ffmpeg가 그 파일을 연 실제 시각입니다. 내용 5초가 벽시계 5초에 만들어졌다면 연속한 이름의 간격이 5초입니다. 간격이 6초 이상이면 내용이 벽시계보다 느리게 쌓이는 것, 즉 드리프트입니다.

세그먼트는 움직임이 없으면 약 12초 후 삭제되므로 90초 동안 수집합니다. 감시 중에 실행합니다.

```bash
SPOOL="$HOME/Library/Application Support/MacMonitor/Spool"; for _ in $(seq 1 90); do ls "$SPOOL" 2>/dev/null; sleep 1; done | grep -o 'segment-[0-9]\{8\}T[0-9]\{6\}\.mp4' | sort -u | sed -e 's/^segment-//' -e 's/\.mp4$//' | awk '{ h=substr($0,10,2); mi=substr($0,12,2); s=substr($0,14,2); t=h*3600+mi*60+s; if (NR>1) print t-prev; prev=t }'
```

출력은 간격의 목록입니다. **모두 5가 나와야 합니다.** 6이나 7이 섞여 나오면 드리프트가 남아 있습니다. 자정을 넘기면 계산이 틀어지므로 그때는 다시 측정합니다.

### G-3. 병합 파일이 CFR 15fps인지

E절에서 만든 사건 파일 하나를 확인합니다.

```bash
ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=avg_frame_rate,nb_read_frames,duration -of default=noprint_wrappers=1 "$HOME/Library/Application Support/MacMonitor/Recordings/motion-"*.mp4
```

`avg_frame_rate`가 `15/1`이고 `nb_read_frames`가 `duration × 15`에 거의 일치해야 합니다. 크게 어긋나면 인코딩 단계에서 프레임레이트가 유지되지 않은 것입니다.

### G-4. 장시간 누적 확인

드리프트는 누적되는 성질이므로 짧은 측정으로는 놓칠 수 있습니다. 1시간 이상 연속 가동한 뒤 G-2를 다시 측정해 간격이 여전히 5초인지 확인합니다.

## H. 앱 비밀번호

1. 최초 실행에서 12자 이상의 비밀번호를 등록한다. 취소하면 감시 없이 종료되어야 한다.
2. 재실행 후 잘못된 비밀번호로 감시/설정에 접근할 수 없는지, 3회 실패 시 종료되는지 확인한다.
3. 올바른 비밀번호로 실행하고 설정에서 변경한 뒤 재실행해 새 비밀번호만 통과하는지 확인한다.
4. 키체인 접근 거부 시 새 비밀번호 등록으로 우회되지 않고 오류로 종료되는지 확인한다.

## I. 보존 시간과 무동작 구간

1. 전 60초 / 후 30초로 설정하고 감시를 다시 시작한다. 최소 70초 동안 버퍼를 채운다.
2. 화면에 시계를 보이게 두고 움직임을 만든 뒤 마지막 움직임부터 100초 기다린다.
3. 사건에 감지 전 약 60초와 마지막 감지 후 약 30초가 포함되는지 확인한다. 5초 세그먼트 단위여서 각 경계가 최대 약 5초 더 포함될 수 있다.
4. 충분히 긴 무동작 구간에서 새 사건이 생기지 않고 오래된 임시 버퍼가 제거되는지 확인한다.
5. 연속 움직임은 사후 구간이 연장되고 같은 사건으로 병합되는지 확인한다.

## J. 예약 잠자기·깨우기

1. 기존 시스템 전원 예약을 기록한 후 `시스템 잠자기 → 깨운 직후 화면 끄기`를 선택하고 잠자기를 현재보다 3분 뒤, 깨우기를 7분 뒤로 정한다.
2. 저장 시 표시되는 시스템 예약 변경 내용을 확인하고 관리자 인증한다. 인증 취소 시 설정이 바뀌지 않아야 한다.
3. 앱을 실행한 채 기다려 잠자기 약 1분 전 감시 중지와 assertion 해제를 확인한다.
4. 실제 시스템 잠자기, 예약 깨우기, 앱 비밀번호 재입력 없이 카메라·녹화·게이트웨이 재개를 확인한다.
   키보드·마우스를 건드리지 않고 깨우기 약 1초 뒤 화면이 다시 꺼지는지 관찰한다. 화면이 잠깐 켜질 수 있다. 이후 마우스로 화면을 켜면 다시 강제로 꺼지지 않아야 한다.
5. 다시 로그인한 경우에는 앱 비밀번호 입력 전 감시가 시작되지 않아야 한다.
6. 자정을 넘는 23:00~06:00 설정도 확인한다. 수동으로 조기 깨운 경우 휴식 구간 동안 감시하지 않아야 한다.
7. 예약을 끄고 저장하면 반복 예약이 취소되는지 확인한다. 테스트 전에 다른 예약이 있었다면 복원한다.

macOS의 전원 예약은 다른 앱의 잠자기 방지와 하드웨어에 영향을 받는다. 화면 끄기는 잠금 해제가 아니며 OS 로그인 잠금을 해제하지 않는다. 앱을 종료하면 시스템 예약은 남지만 감시는 재개되지 않는다. 화면 끄기 실패는 macOS Console에서 `MacMonitor: display sleep failed`로 확인한다.

공식 참고: [Apple 전원 예약 안내](https://support.apple.com/en-bh/guide/mac-help/mchl40376151/mac), [NSWorkspace 잠자기 알림](https://developer.apple.com/documentation/appkit/nsworkspace/willsleepnotification).

## K. 시스템 유지 · 화면만 끄기

1. `시스템 유지 · 화면만 끄기`를 선택하고 휴식 시작을 2분 뒤, 재개를 5분 뒤로 정한다. 이전 모드가 시스템 잠자기였다면 반복 예약 해제 인증이 나오는지 확인한다. 취소하면 앱 설정이 유지되어야 한다.
2. 기존 시스템 예약이 없는 상태에서 이 모드의 시각만 변경하면 관리자 인증 없이 저장되어야 한다. `pmset -g sched`가 바뀌지 않는지 확인한다.
3. 휴식 시각부터 최대 10초 이내 감시 중단과 화면 꺼짐을 확인한다. 카메라·FFmpeg가 중단되어도 `pmset -g assertions`에서 화면 전용 예약의 시스템 유휴 잠자기 방지가 남아 있어야 한다.
4. 재개 시각까지 시스템이 잠들지 않고, 화면을 켜는 명령 없이 감시가 재개되는지 확인한다. 휴식 중 녹화가 없어야 한다.
5. 휴식 중 마우스로 화면을 깨운 뒤 30초 기다려 강제로 다시 꺼지지 않는지 확인한다. 화면 전원 끄기는 화면 잠금과 별개다.
6. 예약 해제·모드 전환·앱 종료 후 화면 전용 assertion이 해제되는지 확인한다(감시 중에는 별도 감시 assertion이 남을 수 있음).
7. 시스템 잠자기로 전환하면 시스템 예약이 등록되고 화면 전용 assertion은 없어지는지 확인한다. 테스트 이전 예약을 복원한다.

## 판정 기록

## L. 원격 시청 대기 (핵심 기능)

HTTPS, 외부 WebRTC 호스트, 포트포워딩을 마친 뒤 수행합니다. 움직임 녹화는 켜지 않습니다.

1. 앱 실행 직후 메뉴의 `원격 시청 대기` 체크와 상태 `원격 시청 대기 중`, 꺼진 카메라 표시등을 확인합니다.
2. `pmset -g assertions`에서 MacMonitor의 `PreventUserIdleSystemSleep`을 확인하고, 설정한 시간 뒤 화면만 꺼지고 시스템은 잠들지 않는지 확인합니다.
3. 휴대폰 데이터망으로 로그인합니다. `카메라 켜는 중…` 뒤 영상이 나오고 표시등이 켜지는지 확인하고 걸린 시간을 기록합니다. 메뉴 상태는 `원격 시청 중 — 녹화 안 함`이어야 합니다.
4. 시청 중 `Spool`과 `Recordings`에 새 파일이 생기지 않고, 웹 상태판의 움직임 녹화가 `꺼짐`인지 확인합니다.
5. 녹화 탭으로 옮기거나 창을 닫거나 휴대폰을 잠그면 약 20초 뒤 표시등이 꺼지는지 확인합니다. 돌아오면 다시 켜져야 합니다.
6. **화면이 꺼진 상태와 Apple 메뉴로 잠근 상태에서 각각 접속합니다.** 카메라가 새로 시작되어 영상이 나와야 하고, iMac 화면이 켜지거나 잠금이 풀리면 안 됩니다. 이 기능의 가장 큰 미검증 위험입니다.
7. 시청 중 `움직임 녹화 시작`을 누릅니다. 플레이어가 스스로 다시 연결되고 움직임 사건이 저장되어야 합니다. `움직임 녹화 중지`를 눌러도 시청이 이어져야 합니다.
8. 시청 중 메뉴의 `원격 시청 대기`를 끕니다. 영상이 끊기고 표시등이 꺼져야 하며, 웹은 저장된 녹화만 보여야 합니다. 다시 켜면 접속할 수 있어야 합니다.
9. 표준·절약 화질을 각각 선택해 재생되는지 확인합니다. 자동 모드 첫 연결이 표준에서 시작하므로 시작 시간도 기록합니다.

## M. 텔레그램 명령

`docs/SETUP_MAC.md` 7절대로 봇을 연결한 뒤 수행합니다.

1. 휴대폰에서 봇에게 `카메라`를 보냅니다. 수 초 안에 `카메라를 켭니다 · https://… · 10분 동안 유지합니다` 답장이 오고, 이어서 `카메라가 켜졌습니다 (N초)` 답장이 와야 합니다. N을 기록합니다.
2. 답장의 링크를 열어 영상이 나오는지 확인합니다. 메뉴 상태는 `원격 시청 중 — 녹화 안 함`이어야 합니다.
3. 웹을 닫고 10분 뒤 카메라 표시등이 꺼지는지 확인합니다. 그 전에 `그만`을 보내면 약 20초 뒤 꺼져야 합니다.
4. `상태`를 보내 앱 상태와 디스크 여유가 오는지 확인합니다. 아무 말이나 보내면 명령 목록이 와야 합니다.
5. 다른 텔레그램 계정으로 봇에게 `카메라`를 보냅니다. 답장도 카메라 켜짐도 없어야 하고 `gateway.log`에 `ignored a message from chat …`만 남아야 합니다.
6. 앱에서 `원격 웹 다시 시작`을 누른 뒤 다시 `카메라`를 보내 봇이 살아 있는지, 이전 명령이 다시 처리되지 않는지 확인합니다.

## N. 원격 녹화

HTTPS와 포트포워딩을 마친 뒤 휴대폰으로 수행합니다.

1. 실시간 화면에서 `원격 녹화` 시간을 `1시간`으로 고르고 `녹화 시작`을 누릅니다. 영상이 잠시 끊긴 뒤 다시 나오고, 버튼이 `녹화 중지`로 바뀌며 `원격 녹화 중 · HH:MM까지 · 남은 …`이 보여야 합니다.
2. 10초 안에 메뉴가 `원격 녹화 중 — 카메라 · HH:mm까지`가 되는지, 웹 상태판의 `녹화` 칸이 `켜짐 · 원격`인지 확인합니다.
3. **웹을 닫고 휴대폰을 잠근 뒤 10분 이상 기다립니다.** 카메라 표시등이 계속 켜져 있어야 하고 `Recordings`에 `remote-*.mp4`가 10분마다 생겨야 합니다. 다시 접속하면 같은 녹화 중 표시와 남은 시간이 보여야 합니다.
4. 파일을 웹 목록에서 재생하고 썸네일이 만들어지는지 확인합니다.
5. `녹화 중지`를 누릅니다. 약 10초 안에 카메라가 꺼지고(시청 중이 아니면) 마지막 짧은 파일이 `Recordings`로 옮겨지며 `Spool`이 비어야 합니다. Mac 메뉴의 `원격 녹화 중지`도 같은 효과여야 합니다.
6. 다시 `1시간`으로 시작하고 끝까지 기다려 그 시각에 스스로 꺼지는지 확인합니다.
7. 녹화 중 `움직임 녹화 시작`을 눌러도 원격 녹화가 유지되는지(모드는 원격이 이김), 끝나면 움직임 녹화로 바뀌는지 확인합니다.
8. 메뉴의 `원격 시청 대기`를 끄면 원격 녹화도 멈추고, 웹에서 `녹화 시작`을 눌러도 카메라가 켜지지 않는지 확인합니다.
9. `최대 녹화 용량 (GB)`를 작게 바꾸어 오래된 `remote-*.mp4`부터 지워지는지 확인합니다.

## O. 슬림 모드 (전원)

가장 먼저 1번을 확인합니다. 화면이 켜지면 이 모드는 요구사항 7과 충돌합니다.

1. `./scripts/enable-slim-mode.sh`를 실행하고 `sudo -n -l /usr/bin/pmset schedule wake probe`가 성공하는지 확인합니다.
2. 설정에서 `슬림 모드`를 켜고 간격 5분으로 저장합니다. 메뉴 상태에 `· 슬림 모드`가 붙어야 합니다.
3. Mac을 건드리지 않고 기다립니다. 약 1분 뒤(입력이 10분 이상 없었다면) Mac이 잠들어야 합니다. 잠들기 직전 `pmset -g sched`에 `wake at … by 'MacMonitor'`가 있어야 합니다. Console에서 `MacMonitor:` 로그를 봅니다.
4. 약 5분 뒤 스스로 깨어나는지 확인합니다. **이때 화면이 켜지는지 반드시 기록합니다.** `pmset -g log | grep -i wake`에서 `DarkWake`인지 `Wake`인지 적습니다. 화면이 켜졌다면 약 1초 뒤 다시 꺼져야 합니다.
5. 깨어난 뒤 약 1분 안에 다시 잠드는지 확인합니다. 세 주기 이상 반복되는지 봅니다.
6. 잠든 동안 텔레그램으로 `카메라`를 보냅니다. 다음 깨어남에 답장과 링크가 오고 영상이 나와야 합니다. 보는 동안 Mac이 잠들지 않아야 하고, 웹을 닫고 10분이 지나면(또는 `그만` 뒤 약 1분) 다시 잠들어야 합니다.
7. 키보드를 한 번 누른 뒤 10분 동안은 Mac이 잠들지 않는지 확인합니다.
8. 웹에서 원격 녹화를 `1시간`으로 시작하고 웹을 닫은 뒤 Mac을 건드리지 않습니다. 녹화가 끝나기 전에는 잠들지 않고, 끝난 뒤 약 1분 안에 잠드는지 확인합니다.
9. 슬림 모드를 끄고 저장한 뒤 `pmset -g sched`에서 MacMonitor 항목이 사라지는지, Mac이 다시 깨어 있는 대기를 유지하는지 확인합니다.
10. `IOPMSchedulePowerEvent`를 root 없이 호출할 수 있는지 별도 확인합니다. 가능하면 sudoers 규칙 없이 구현할 수 있습니다.

## P. 소리

1. 새 빌드의 첫 카메라 시작(웹 접속 또는 텔레그램 `카메라`)에 마이크 권한 창이 뜨는지 확인하고 허용합니다. 웹 상태판 `소리`가 `켜짐`이어야 합니다. 거부해 보는 경우 `없음 · 마이크 권한 필요`가 뜨고 영상은 계속 나와야 합니다.
2. 실시간 화면 위 `소리 켜기`를 누릅니다. 소리가 나야 하고 버튼이 `소리 끄기`로 바뀌어야 합니다. 카메라 앞에서 손뼉을 세 번 치고 소리와 영상의 어긋남을 봅니다. 0.2초 안이면 정상입니다.
3. 원격 녹화를 1시간 시작한 뒤 생긴 `remote-*.mp4`를 웹에서 재생해 소리를 확인합니다. 터미널에서 `ffprobe -v error -show_entries stream=codec_type,codec_name -of csv=p=0 "$HOME/Library/Application Support/MacMonitor/Recordings/remote-"*.mp4 | sort -u`에 `audio,aac`와 `video,h264`가 보여야 합니다.
4. 1시간 뒤 2번의 손뼉 시험을 다시 합니다. 어긋남이 늘지 않아야 합니다. Console에서 `MacMonitor audio:` 줄을 찾아 padded·trimmed·dropped 값을 기록합니다(줄이 없으면 보정 0회).
5. 화질을 `표준`과 `절약`으로 바꿔도 소리가 나는지 확인합니다.
6. `./scripts/diagnose.sh`에서 `FFmpeg provides libopus and aac`와 `FFmpeg encoded sound with Opus and AAC through the tee`가 pass인지 봅니다. warn이면 문구를 기록하고 진단 폴더의 `ffmpeg.log`를 보존합니다.
7. 설정에서 `소리`를 끄고 저장한 뒤 카메라를 다시 시작합니다(`원격 시청 대기`를 껐다 켜기). 상태판이 `꺼짐 (설정)`이고 새 파일에 `audio` 줄이 없어야 합니다.

## Q. 웹에서 녹화 삭제

1. 녹화 탭에서 보호하지 않은 녹화의 `삭제`를 누르고 확인 창에서 취소합니다. 아무것도 바뀌지 않아야 합니다.
2. 다시 `삭제` → 확인. `녹화를 삭제했습니다`와 함께 목록에서 사라지고 `Recordings` 폴더에서도 없어져야 합니다.
3. `중요 녹화로 보호`한 녹화의 `삭제`가 비활성인지, `보호 해제` 뒤 삭제되는지 확인합니다.
4. 삭제한 녹화의 미리보기 주소를 다시 열면 404여야 합니다.
