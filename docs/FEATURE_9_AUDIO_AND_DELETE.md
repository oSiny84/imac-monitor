# 기능 9 — 소리(실시간·녹화)와 웹에서 녹화 삭제

2026-11-08 저녁 구현. 사용자의 요청은 "소리도 나오고 녹화도 되어야 한다"와 "웹에서 녹화된 것을 삭제하는 기능"입니다. Swift 부분은 이 작업 환경(Windows)에서 컴파일되지 않았고, 마이크·동기화·WebRTC 소리는 대상 iMac에서만 판정할 수 있습니다. 확정된 것과 확인이 필요한 것을 §4에서 구분합니다.

## 1. 요약

| 요청 | 설계 결정 | 판단 |
|---|---|---|
| 실시간 영상에 소리 | 카메라 세션에 기본 마이크를 더해 48kHz 모노 16비트 PCM을 받고, 영상과 같은 FFmpeg에 두 번째 입력(이름 있는 파이프)으로 넣습니다. 실시간은 Opus, 녹화 파일은 AAC로 한 번씩 인코딩해 tee의 `select`로 갈라 보냅니다. | 구현. 마이크 권한·동기화·브라우저 재생은 **Mac에서 확인** |
| 녹화 파일에 소리 | 같은 파이프라인의 세그먼트 출력이 AAC 트랙을 받습니다. 화질 프로필 재인코딩도 소리를 그대로 통과시킵니다. | 구현 |
| 소리 켜고 끄기 | 설정 창 `소리` 체크(기본 켜짐). 끄면 다음 카메라 시작부터 소리 없이 동작합니다. | 구현. 기본값 켜짐은 사용자가 소리를 요청했기 때문입니다 |
| 소리가 안 될 때 | 마이크 권한 거부, 마이크 없음, FFmpeg에 `libopus`·`aac` 없음, FFmpeg가 소리 명령을 거부함 중 어느 경우에도 카메라는 소리 없이 계속 켜지고, 이유를 메뉴·웹 상태판·텔레그램 `상태`에 보여 줍니다. | 구현(fail-soft) |
| 웹에서 녹화 삭제 | 녹화 카드의 `삭제` 버튼. 확인 창을 거치고, 보호된 녹화는 먼저 보호를 해제해야 합니다. 게이트웨이는 보관 관리자와 같은 잠금을 잡고 지웁니다. | 구현 |

## 2. 소리

### 2.1 캡처

`CameraCaptureService`가 카메라 권한을 받은 직후 마이크 권한도 요청합니다(`requestAuthorization`). 마이크를 거부해도 완료 값은 참이라 카메라는 그대로 시작합니다. 세션 구성 때 `configureAudio()`가 기본 마이크 입력과 `AVCaptureAudioDataOutput`을 더하고 `audioSettings`로 48kHz·1채널·16비트 정수·인터리브 형식을 지정합니다. 그 바이트가 곧 FFmpeg의 `s16le` 입력입니다. 첫 버퍼의 형식이 요청과 다르면 소리를 버리고 로그를 남깁니다. 결과는 `CaptureRuntimeInfo.audio`(`on`/`off`/`unavailable(이유)`)로 전달됩니다.

필요한 메타데이터: `Info.plist`의 `NSMicrophoneUsageDescription`(없으면 macOS가 마이크 접근 시 앱을 종료), 서명 entitlement `com.apple.security.device.audio-input`. `diagnose.sh`가 둘 다 확인합니다.

### 2.2 영상과의 동기화

원시 입력에는 타임스탬프가 없습니다. FFmpeg는 영상을 프레임 수로, 소리를 샘플 수로 시간에 놓습니다. 그래서 "지금까지 쓴 샘플 수 = 내보낸 프레임 수 × 48000 / 15"가 항상 유지되어야 두 흐름이 맞습니다. `AudioTimelineAligner`가 이를 맡습니다.

- 첫 영상 프레임 전의 소리는 버립니다. 카메라가 마이크보다 늦게 시작하는 1~2초가 전체 오프셋이 되지 않도록 하기 위해서입니다.
- 소리가 영상보다 0.15초 넘게 뒤지면(마이크 멈춤, 파이프가 가득 차 버린 샘플) 그만큼 무음을 채웁니다.
- 소리가 0.15초 넘게 앞서면(마이크 클럭 드리프트) 목표까지만 남기고 자릅니다.
- 허용 폭 0.15초는 영상 한 프레임(67ms)과 소리 한 덩어리(21ms)의 교대 리듬보다 넓어, 정상 상태에서는 어떤 보정도 일어나지 않습니다. 보정 횟수는 1분마다 로그에 남기고, 0이 목표입니다.

### 2.3 FFmpeg 명령

`FFmpegPipeline`이 `Runtime/audio-<id>.pcm` 이름 있는 파이프를 `mkfifo`로 만들고 `O_RDWR | O_NONBLOCK`으로 엽니다. 읽기·쓰기 양쪽으로 여는 이유는 FFmpeg와 앱 어느 쪽도 상대가 열 때까지 막히지 않게 하고, FFmpeg가 죽어도 SIGPIPE가 나지 않게 하기 위해서입니다. 쓰기는 비차단이며, 파이프가 가득 차면 그 샘플은 버리고 정렬기가 나중에 무음으로 메웁니다.

```text
-f rawvideo … -i pipe:0
-f s16le -ar 48000 -ac 1 -i Runtime/audio-….pcm
-map 0:v:0
-map 1:a:0 -c:a:0 libopus -b:a:0 48k        ← 실시간(WebRTC는 Opus만 재생)
-map 1:a:0 -c:a:1 aac    -b:a:1 64k         ← 파일(Safari가 재생하는 AAC)
-c:v h264_videotoolbox -realtime:v … (영상 옵션에 :v 지정)
-f tee "[f=rtsp:…:select=0,1]rtsp://…|[f=segment:…:select=0,2]Spool/…"
```

`select`는 출력 스트림 번호(0 영상, 1 Opus, 2 AAC, `-map` 순서)로 고릅니다. 처음에는 `select='v:0,a:0'`처럼 썼는데, tee는 따옴표와 상관없이 `:`마다 옵션을 끊어 `No option found near "0,a:0]-"`로 실패했습니다. 2026-11-10 대상 iMac(evermeet 빌드)에서 이 때문에 소리 시험이 실패해 소리가 꺼졌고, Windows의 FFmpeg 7.1에서도 같은 오류를 재현했습니다. 번호로 바꾼 명령은 7.1에서 실시간 쪽에 영상+Opus, 파일 쪽에 영상+AAC만 들어가는 것을 ffprobe로 확인했습니다.

기존 영상 전용 명령은 소리가 없을 때 그대로 유지되어(`-an`, `select` 없음) 지금까지 검증된 모양을 바꾸지 않습니다. 용량은 시간당 약 0.03GB가 늘어납니다.

### 2.4 FFmpeg 능력 확인과 fail-soft

`FFmpegCapabilities`가 FFmpeg 하나당 한 번 `-encoders`를 읽어 `libopus`·`aac`를 확인하고, `/dev/zero`를 두 입력으로 삼아 0.2초짜리 시험 인코딩을 위 명령과 같은 모양으로 돌립니다. 둘 중 하나라도 실패하면 `LocalMonitoringPipeline`은 소리 없는 명령으로 카메라를 켜고 이유를 `MonitoringHealthReporter.setAudioEncoder(problem:)`로 보냅니다. 처음 작성할 때는 Windows에서 실제 FFmpeg를 돌려 보지 않았고, 이 시험 인코딩이 Mac에서 위 `select` 오류를 처음 드러냈습니다. `diagnose.sh`도 같은 명령을 실행해 결과를 보여 줍니다.

### 2.5 상태 표시

상태 파일에 `audio`(`on`/`off`/`unavailable`)와 `audioDetail`(이유)이 추가되었습니다. 게이트웨이는 허용 값을 검사하고, 웹 상태판의 `소리` 칸은 `켜짐`/`꺼짐 (설정)`/`없음 · 이유`를 보입니다. Mac 메뉴는 `· 소리 없음 — 이유`, 텔레그램 `상태`는 `· 소리 없음 (이유)`를 붙입니다.

### 2.6 웹 플레이어

WHEP 제안에 오디오 트랜시버를 더해 Opus 트랙을 받습니다. 브라우저는 소리 있는 영상을 자동 재생하지 않으므로 음소거로 시작하고, 화면의 `소리 켜기` 버튼을 누르면 켜집니다. 선택은 기억되며, 다음 접속에서 소리 있는 자동 재생이 거부되면 음소거로 되돌려 재생하고 `소리 켜기를 누르면 소리가 납니다`를 상태 줄에 붙입니다. 표준·절약 화질은 FFmpeg 재인코딩을 거치는데, 그 명령의 `-an`을 `-map 0:a? -c:a copy`로 바꿔 소리가 그대로 지나갑니다.

### 2.7 경계

- 마이크는 시스템 기본 장치입니다. 선택 UI는 없습니다.
- 텔레그램 `카메라`로 켠 실시간 시청도 같은 스트림이므로 소리가 있습니다.
- 소리 설정 변경은 다음 카메라 시작부터 적용됩니다(설정 창에 명시).
- 사생활: 집 안 소리가 원격으로 전달됩니다. 기본 켜짐은 사용자의 명시적 요청이며, 설정에서 끌 수 있습니다. 마이크 사용 중에는 macOS가 메뉴 막대에 주황 표시를 보입니다.

## 3. 웹에서 녹화 삭제

- 게이트웨이 `DELETE /api/recordings/{id}`: 세션·Origin·CSRF 검사 뒤 `Store.Delete`. 보관 관리자·보호 쓰기와 같은 `flock`을 잡아 앱의 정리 작업과 겹치지 않습니다. 보호된 녹화는 409(`먼저 보호를 해제하세요`), 없는 파일은 404, 정리 중인 `segment-` 파일은 400, 보호 상태를 읽을 수 없으면 503으로 거부하고 파일을 건드리지 않습니다. 보호 상태가 불명확할 때 지우지 않는 것은 보호의 "안전 쪽으로 실패" 원칙과 같습니다.
- 웹: 녹화 카드의 `삭제` 버튼은 확인 창을 거치고, 보호된 녹화에서는 비활성입니다. 성공하면 목록을 새로 고치고 `녹화를 삭제했습니다`를, 거부되면 서버의 이유를 보여 줍니다. 썸네일 캐시는 파일 상태를 다시 확인하므로 지운 녹화의 미리보기가 남지 않습니다.

## 4. Mac에서 확인해야 하는 것 (미확인)

위에서부터 중요한 순서입니다.

1. 첫 카메라 시작에 마이크 권한 창이 뜨고 허용 뒤 웹 상태판 `소리`가 `켜짐`인지. 거부하면 `없음 · 마이크 권한 필요`로 카메라는 계속 켜지는지.
2. 실시간 화면에서 `소리 켜기`를 누르면 소리가 나는지. 카메라 앞에서 손뼉을 치고 영상과 소리의 어긋남을 봅니다(0.2초 안이면 정상).
3. 녹화 파일(`remote-*.mp4`)을 웹에서 재생할 때 소리가 나는지. 터미널에서 `ffprobe -v error -show_entries stream=codec_type,codec_name -of csv=p=0 <파일>`로 `audio,aac` 줄이 보여야 합니다.
4. 1시간 녹화 뒤 같은 손뼉 시험을 다시 해 어긋남이 늘지 않았는지. Console의 `MacMonitor audio:` 줄에서 padded·trimmed·dropped가 0에 가까운지.
5. 표준·절약 화질에서도 소리가 나는지.
6. `diagnose.sh`의 `FFmpeg encoded sound with Opus and AAC through the tee`가 pass인지. warn이면 그 문구를 기록합니다. 앱 메뉴에 `소리 없음 — FFmpeg …`가 보이면 `ffmpeg.log`를 함께 보냅니다.
7. 설정에서 `소리`를 끄고 카메라를 다시 시작하면 `꺼짐 (설정)`이 되고 파일에 오디오 트랙이 없는지.
8. 웹에서 녹화 하나를 삭제하면 목록·`Recordings` 폴더에서 사라지는지. 보호된 녹화의 `삭제`가 비활성인지.
9. Swift 소스 전체의 컴파일과 새 XCTest(`AudioTimelineAlignerTests` 6개, `FFmpegCapabilitiesTests` 3개, `FFmpegPipelineTests` 3개 추가 등).

## 5. 검증

실행한 검사 (Windows, 2026-11-08):

- Go: `go vet`, `go test ./...` 전체 통과. 새 테스트: 저장소 `Delete`(보호·없음·세그먼트·손상 메타데이터), 서버 `DELETE`(세션·Origin·CSRF·409·204·404), 상태 파일 `audio` 허용 값, 텔레그램 `상태`의 소리 없음 문구. 삭제 테스트 2개는 구현 전 컴파일 실패를 확인했습니다.
- Node 53개 통과. 새 테스트: 삭제 흐름(확인 창·CSRF·보호 비활성·거부 메시지), 플레이어의 오디오 트랜시버와 `소리 켜기` 토글, 소리 자동 재생 거부 시 음소거 복귀, 상태판 `소리` 칸. 모두 페이지를 바꾸기 전에 실패하는 것을 확인했습니다.
- 스크립트 회귀 검사 32개 통과. FFmpeg 모의 출력에 `libopus`·`aac`를 더해 진단·빌드 스크립트의 인코더 확인 줄이 계속 검사됩니다.
- Swift: 컴파일하지 않았습니다. `AudioTimelineAligner`는 순수 로직이라 테스트로 동작을 고정했고, 캡처·파이프·FFmpeg 명령은 Mac 빌드가 첫 확인입니다.

실행하지 못한 검사: §4 전부. 특히 실제 FFmpeg의 tee `select` 문법 수용 여부는 앱의 시험 인코딩과 `diagnose.sh`가 Mac에서 처음 확인합니다.
