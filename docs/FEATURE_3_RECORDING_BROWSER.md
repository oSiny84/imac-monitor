# 기능 3 — 녹화 날짜 검색·썸네일·다운로드

2026-10-20 구현. 기존 로그인과 감시 독립 녹화 접근을 유지합니다. 후속 중요 녹화 보호는 [기능 4 기록](FEATURE_4_RECORDING_PROTECTION.md)에 있습니다.

## 사용 방법

로그인 후 녹화 탭에서 시작·끝 날짜를 선택하고 `날짜 검색`을 누릅니다. 한쪽 날짜만 지정할 수도 있고, `전체 보기`로 조건을 지웁니다. `새로고침`은 적용된 날짜 조건을 유지하면서 첫 페이지로 돌아갑니다.

- 날짜와 목록의 시각은 **접속 기기 현지 시간대** 기준입니다. 화면에 시간대를 표시합니다. iMac의 시간대와 다르면 그 차이가 적용됩니다.
- 녹화 **시작 시각**을 검색합니다. 시작 날짜의 0시부터 끝 날짜 다음 날 0시 직전까지 포함합니다. 날짜 중간에 걸친 긴 녹화의 전체 구간 겹침 검색은 아닙니다.
- 일광 절약 시간제의 23/25시간 날짜를 고려해 다음 현지 날짜의 0시를 계산합니다. 날짜 순서가 뒤집히거나 유효하지 않으면 요청하지 않습니다.
- 최신 녹화부터 50개씩 표시하며 이전·다음 버튼과 결과 개수를 제공합니다. 동시에 추가·삭제되는 파일의 고정 스냅샷은 아니므로 페이지 사이에 항목이 이동할 수 있습니다. 새로고침하면 현재 목록을 다시 읽습니다.
- 카드를 누르면 그 영상만 재생하고, 다른 영상은 닫습니다. 목록만 볼 때는 MP4를 미리 받지 않습니다. 실시간 탭으로 이동하면 녹화 재생을 멈춥니다.
- `원본 MP4 다운로드`는 재압축하지 않은 원본 파일을 내려받습니다. Range/HEAD를 지원합니다. 실제 저장 위치·공유 화면·이어받기 방식은 Safari 등 브라우저가 결정합니다.

## 미리보기와 자원 제한

브라우저는 화면 근처의 썸네일을 지연 로딩합니다. 게이트웨이는 요청된 영상의 첫 프레임을 최대 320×180 JPEG로 만듭니다. 감지 전 보존 구간이 있으므로 첫 프레임에 움직이는 물체가 보인다는 보장은 없습니다. 기존 녹화도 소스를 변경하지 않고 처리합니다.

- FFmpeg는 앱의 게이트웨이 실행 파일 옆, `/usr/local/bin/ffmpeg`, `/opt/homebrew/bin/ffmpeg` 순으로 찾습니다. 추가 설정은 필요하지 않습니다.
- 동시 디코더 1개, 디코딩 최대 8초, 대기 포함 요청 최대 12초, JPEG당 256KiB 제한입니다. 입력·출력·스케일 필터 스레드 수를 제한합니다. 4K에서도 원본 전체를 휴대폰으로 전송하지 않지만, iMac의 첫 프레임 디코딩 비용까지 없어지는 것은 아닙니다.
- 최근 128개만 메모리에 보관합니다(압축 JPEG 데이터 최대 32MiB, 런타임 부가 메모리 별도). 앱/게이트웨이 재실행 시 비워집니다. 디스크 썸네일 파일은 만들지 않습니다.
- 파일 크기나 수정 시각이 바뀌면 다시 생성합니다. 삭제된 파일은 캐시가 남아 있어도 제공하지 않습니다. 이미 열린 다운로드·생성 작업의 수명은 파일 삭제와 별개입니다.
- 손상 영상, FFmpeg 부재·실패·시간 초과 시 `미리보기 없음 · 재생 가능`으로 대체합니다. 재생·다운로드 경로 자체를 막지는 않습니다. 손상 파일이 실제로 재생 가능하다는 보장은 아닙니다.
- 같은 파일의 생성 실패는 30초 동안 기억합니다. 이후 새로고침해서 다시 요청할 수 있습니다.

## 인증과 API

목록·JPEG·다운로드·재생·HEAD 요청 모두 기존 로그인 세션으로 보호합니다. 응답은 `no-store`이며, 서버 메모리 캐시와 브라우저 캐시는 구분합니다. 로그아웃 시 재생 자원·목록을 지우고 이전 검색 응답이 뒤늦게 도착해도 표시하지 않습니다. 이미 내려받은 파일을 원격 삭제하지는 않습니다.

- `GET /api/recordings?from=RFC3339&to=RFC3339&offset=0&limit=50`: 시작 포함/끝 제외. 날짜 경계는 브라우저가 시간대가 포함된 절대 시각으로 보냅니다. `limit`은 1~100, 기본 50. `recordings`, `total`, `hasMore`를 반환합니다. 기존 무조건 전체 목록 응답은 기본 50개 응답으로 바뀝니다.
- `GET /api/recordings/{id}/thumbnail`: 인증된 JPEG. 생성 불가는 503과 Retry-After, 파일 부재는 404입니다.
- `GET /recordings/{id}?download=1`: attachment 원본 MP4. 기존 파라미터 없는 URL은 inline 재생을 유지합니다.

서버는 안전한 MP4 이름과 일반 파일만 받으며 녹화 디렉터리 밖으로 벗어나지 않도록 Go의 디렉터리 제한 파일 열기를 사용합니다. FFmpeg에는 사용자 경로 대신 이미 확인하고 연 seek 가능한 파일 디스크립터를 전달합니다. 검색은 파일 메타데이터를 읽으며 영상 디코딩과 분리되어 있습니다. 대규모 폴더의 영구 검색 인덱스는 이번 범위가 아닙니다.

## 실행한 검사와 남은 검증

- Windows Go 검사: 총 23개 중 21개 통과, 2개 건너뜀. 날짜/페이지 경계, 잘못된 요청, 인증·HEAD·Range 다운로드, 미리보기 실패 후 다운로드, 캐시 변경·삭제·실패·개수 제한, 직렬 실행과 취소를 검사했습니다. `go vet ./...` 및 Darwin/amd64 교차 빌드도 통과했습니다.
- 건너뛴 2개: 심볼릭 링크 검사(Windows 생성 권한 없음), 실제 FFmpeg 파일 디스크립터 통합 검사(macOS/Linux 전용). 후자는 임시 MP4를 만들어 첫 JPEG를 실제 디코딩하는 테스트로, Mac 빌드의 Go 테스트에 포함됩니다.
- Node 화면 제어 검사 9개 통과. 날짜 검색/초기화·뒤집힌/잘못된 날짜·페이지 이동·썸네일 실패·원본 링크·늦은 응답·로그아웃·기존 상태판과 실시간 전환을 확인합니다. 미국 뉴욕 시간대에서도 실행해 DST 시작일의 검색 범위가 23시간임을 확인했습니다. DOM 대역 검사이며 실제 Safari 렌더링 검사는 아닙니다.

현재 환경에서는 Swift 빌드, Mac의 실제 FFmpeg 실행, Safari의 이미지·영상·다운로드, 장시간 성능을 확인하지 못했습니다. 이 변경은 Swift 소스를 수정하지 않았습니다.

## Mac 인수 테스트

1. 최신 ZIP을 새 폴더에 풀어 `Build MacMonitor.command`를 더블클릭합니다. Go 검사에서 `TestThumbnailRealFFmpegWithSeekableDescriptor`가 PASS인지 확인합니다. 실패하면 빌드 로그를 보존합니다.
2. HTTPS 로그인 후 녹화 탭을 엽니다. 작은 이미지·시각·크기를 확인하고, 한 카드를 눌러 재생/닫기를 확인합니다. 다른 카드를 열면 이전 재생이 멈춰야 합니다.
3. 녹화가 있는 날짜 하루를 검색하고 전체 날짜로 되돌립니다. 자정 근처 녹화와 브라우저/iMac 시간대가 다른 경우 시각을 비교합니다. 녹화 없는 날은 빈 목록이어야 합니다.
4. 50개 넘는 녹화가 있다면 이전·다음 페이지와 결과 개수를 확인합니다. 페이지를 바꿀 때 기존 영상이 멈추고, 새로고침은 날짜 조건을 유지하며 첫 페이지로 이동해야 합니다.
5. MP4 다운로드 후 Mac 또는 휴대폰에서 실제 재생·탐색합니다. 원본 파일명과 크기가 일치하는지 확인합니다. 브라우저별 파일 앱/다운로드 목록에서 결과를 확인합니다.
6. 로그아웃 후 이미지·다운로드 주소를 다시 열어 인증이 필요한지 확인합니다. 감시 수동 중지·화면 전용 휴식 중에도 날짜 검색·썸네일·다운로드가 작동해야 합니다(시스템 잠자기 중 원격 접속은 불가).
7. 썸네일 생성 중 CPU·메모리와 촬영 FPS를 관찰하고, 실시간·녹화 탭을 바꿔도 감시·녹화가 계속되는지 확인합니다. 실제 4K 성능이나 끊김 없는 재생을 사전 보장하지 않습니다.
