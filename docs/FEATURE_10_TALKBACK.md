# 기능 10: Mac 스피커로 말하기 (누르고 말하기, 텔레그램 `말`)

2026-11-23 사용자의 요청으로 추가했습니다. 휴대폰에서 보낸 목소리나 글을 iMac 스피커로 들려줍니다. Windows에서 Go 테스트와 스크립트 문법 검사를 했고, 데스크톱 Chrome(`http://127.0.0.1`, 가짜 마이크, 마우스형 포인터 이벤트)에서 누르고 말하기 흐름(녹음 표시, `POST /api/talk?volume=83`·`audio/webm;codecs=opus` 전송, 마이크 해제, 너무 짧은 녹음, 권한 창이 떠 있는 동안 뗀 경우, 거부)을 확인했습니다. 휴대폰 터치, iPhone Safari, 자체 서명 인증서 주소는 확인하지 않았고, 아래 §5의 항목은 Mac과 휴대폰에서 확인해야 합니다.

## 1. 쓰는 법

- **웹 `누르고 말하기`**: 실시간 화면의 버튼을 누르고 있는 동안 휴대폰 마이크로 녹음하고, 떼면 Mac에서 재생합니다. 한 번에 최대 1분입니다. 옆의 `Mac 음량` 막대(1~100)로 재생 음량을 정하고, 값은 그 휴대폰 브라우저에 기억됩니다. 처음 누르면 브라우저가 마이크 권한을 묻습니다. 허용하는 동안 손을 뗐다면 한 번 더 누른 채로 말합니다.
- **텔레그램 `말 …`**: `말 밥 먹었어?`, `말해 …`, `say …`처럼 보내면 Mac이 한국어 목소리로 읽습니다(최대 300자). 2분 넘게 지난 요청은 읽지 않습니다. Mac이 자는 동안 보낸 말이 몇 시간 뒤에 갑자기 나오지 않게 하기 위해서이고, Mac이 화면 없이 잠깐 깬 상태(dark wake)에서는 소리가 나지 않기 때문입니다.
- **텔레그램 `볼륨 70`**: `말`로 읽을 때의 음량(1~100, 기본 60)을 정합니다. 숫자 없이 `볼륨`만 보내면 지금 값을 알려 줍니다. 값은 `Runtime/telegram-state.json`에 남아 게이트웨이가 다시 떠도 유지됩니다. 웹 막대와는 따로입니다.

## 2. 동작

웹과 봇이 게이트웨이 안의 재생기(`gateway/internal/speaker`) 하나를 함께 씁니다. 한 번에 한 소리만 재생하고, 재생 중에 온 요청은 "다른 음성을 재생하고 있습니다"로 거절합니다(웹은 409).

1. **음량**: `osascript`로 지금 출력 음량과 음소거 여부를 읽고, 재생하는 동안만 요청한 음량·음소거 해제로 바꾼 뒤 원래대로 되돌립니다. 읽지 못하면(일부 외부 출력 장치) 음량을 건드리지 않고 재생합니다.
2. **녹음 재생**: 웹이 `POST /api/talk?volume=N`으로 녹음 파일을 보냅니다. 로그인과 CSRF 토큰이 필요하고, `audio/*`(Chrome의 `video/webm` 표기 포함)만 받으며 2 MB까지입니다. FFmpeg로 앞 60초를 WAV로 바꾸고 `/usr/bin/afplay`로 재생합니다. 재생이 끝난 뒤 응답하므로 화면에 `Mac에서 재생했습니다`가 나오면 실제로 재생된 것입니다. 휴대폰 연결이 끊겨도 재생은 끝까지 갑니다.
3. **글 읽기**: `say -v ?` 목록에서 `ko_KR` 목소리(Yuna 우선)를 찾아 `say -v <목소리> -f -`로 읽습니다. 글은 표준 입력으로 넘겨 `-`로 시작하는 글이 옵션으로 읽히지 않게 했습니다. 한국어 목소리가 없으면 내려받을 곳을 답장합니다.
4. **브라우저 권한**: 메인 화면만 `Permissions-Policy: microphone=(self)`로 마이크를 쓸 수 있고, 실시간 영상 프레임(`/live/`)은 계속 `microphone=()`입니다. 녹음 형식은 브라우저가 지원하는 것을 고릅니다(Android Chrome은 WebM/Opus, iPhone Safari는 MP4/AAC). 한 번 보낼 때마다 마이크를 놓아 휴대폰의 마이크 표시가 꺼집니다.

## 3. 알려진 제약

- **HTTPS 경고가 뜨는 주소에서는 마이크가 막힐 수 있습니다.** 브라우저는 안전한 연결(secure context)에서만 마이크를 허용합니다. 자체 서명 인증서를 경고를 무시하고 연 경우 브라우저에 따라 막힐 수 있고, 그때 화면에 `이 연결에서는 브라우저가 마이크를 막습니다`가 나옵니다.
- **재생된 소리가 영상과 녹화에 들어갑니다.** Mac 마이크가 스피커 소리를 다시 받기 때문입니다. 실시간 화면의 소리를 켜 두었다면 1~2초 뒤 내 목소리가 메아리처럼 들립니다.
- **음량 복원은 재생이 끝날 때 합니다.** 재생 도중 Mac이 잠들어 앱이 게이트웨이를 멈추면 음량이 바뀐 채로 남을 수 있습니다.
- **Mac이 자고 있으면 쓸 수 없습니다.** 웹은 Mac이 깨어 있어야 열리고, 텔레그램 `말`은 늦은 요청을 읽지 않습니다. 먼저 `대기`로 깨워 둡니다.

## 4. 바꾼 파일

- `gateway/internal/speaker/speaker.go`(새 파일), `speaker_test.go`
- `gateway/internal/server/server.go`: `POST /api/talk`, `SetTalker`, 메인 화면 `microphone=(self)`. 테스트 `talk_test.go`
- `gateway/internal/server/web/index.html`, `assets/app.js`, `assets/styles.css`: 버튼, 음량 막대, 녹음·전송
- `gateway/internal/chat/telegram.go`: `말`·`볼륨` 명령, 도움말. 테스트 `telegram_test.go`
- `gateway/internal/recordings/thumbnail.go`: FFmpeg 찾기 함수를 `LocateFFmpeg`로 공개해 재생기도 같은 FFmpeg를 씀
- `gateway/cmd/macmonitor-gateway/main.go`: 재생기 하나를 웹과 봇에 연결

## 5. Mac과 휴대폰에서 확인할 것

1. 휴대폰에서 `누르고 말하기`를 한 번 누르면 마이크 권한을 묻는지, 아니면 `이 연결에서는 브라우저가 마이크를 막습니다`가 나오는지. 쓰는 휴대폰·브라우저와 함께 기록합니다.
2. 누른 채 말하고 떼면 Mac 스피커로 나오고 화면에 `Mac에서 재생했습니다`가 나오는지.
3. Mac 음량을 낮추거나 음소거해 둔 상태에서 막대를 80으로 두고 보내면 80으로 들리고, 재생 뒤 원래 음량·음소거로 돌아가는지(`osascript`가 게이트웨이 프로세스에서 동작하는지).
4. 텔레그램 `말 안녕하세요`가 한국어 목소리로 나오는지. 목소리가 없다는 답장이면 손쉬운 사용 → 음성 콘텐츠에서 Yuna를 내려받고 다시 보냅니다.
5. 휴대폰에서 버튼을 5초쯤 누르고 있어도 글자 선택·돋보기·길게 누르기 메뉴가 뜨거나 화면이 스크롤되지 않는지.
6. 1분 가까이 녹음했을 때도 재생되는지. 짧은 녹음은 되고 긴 녹음만 네트워크 오류로 실패하면 약한 데이터망에서 게이트웨이의 요청 읽기 제한 30초에 걸린 것일 수 있습니다.
7. 재생 중에 하나 더 보내면 "다른 음성을 재생하고 있습니다"가 나오는지.
