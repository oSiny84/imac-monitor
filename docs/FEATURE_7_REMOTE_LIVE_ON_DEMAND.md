# 기능 7 — 원할 때만 켜지는 원격 실시간 영상

2026-11-07 구현. 이 앱의 핵심 기능을 원격 실시간 시청으로 바꿨습니다. 평소에는 카메라를 끄고 대기하다가, 로그인한 시청자가 실시간 화면을 열 때만 카메라를 켭니다. 움직임 녹화는 필요할 때 메뉴에서 켜는 부가 기능입니다.

## 요약

| 항목 | 이전 | 이후 |
|---|---|---|
| 앱 시작 직후 | 카메라 꺼짐, 원격 실시간 불가 | 카메라 꺼짐, 접속하면 켜짐 |
| 원격 실시간 조건 | Mac 앞에서 `감시 시작`을 눌러 둬야 함 | 앱 실행·인증 상태면 됨 |
| 실시간만 볼 때 | 항상 녹화 파이프라인 동작 | 감지·임시 버퍼·녹화 파일 없음 |
| 카메라 표시등 | 감시 중 계속 켜짐 | 보는 동안만 켜짐 |
| 시청 종료 | 해당 없음 | 약 20초 뒤 카메라 꺼짐 |
| 대기 중 잠자기 | 감시를 끄면 Mac이 잠들어 접속 불가 | 화면은 꺼져도 시스템은 깨어 있음 |

## 동작

- 메뉴 `원격 시청 대기`가 켜져 있으면(기본값) 로그인한 웹 시청자가 카메라를 켤 수 있습니다. 끄면 원격에서 카메라를 켤 수 없고, 보고 있던 영상도 바로 끊깁니다. 웹의 녹화 목록·재생은 그대로 씁니다.
- 실시간 화면을 보이는 동안 웹 페이지가 5초마다 시청 요청을 갱신합니다. 앱은 이 요청이 20초 동안 없으면 카메라를 끕니다. 녹화 탭으로 옮기거나, 창을 닫거나, 브라우저를 백그라운드로 보내면 요청이 멈춥니다.
- 카메라를 켜는 동안 화면에 `카메라 켜는 중…`을 표시합니다. 예전처럼 녹화 탭으로 넘어가지 않습니다. 45초가 지나도 영상이 없으면 Mac과 앱 상태를 확인하라고 안내합니다.
- 메뉴 `움직임 녹화 시작`을 누르면 감지·임시 버퍼·녹화가 켜지고 카메라는 계속 켜져 있습니다. 시청자도 같은 영상을 봅니다. 시청 중에 녹화를 켜거나 끄면 인코더 출력이 달라져 카메라가 다시 시작되고, 플레이어는 스스로 다시 연결합니다.
- 예약 휴식은 녹화만 쉬게 합니다. 휴식 중이라도 Mac이 깨어 있으면 시청자가 영상을 열 수 있습니다.
- 재시도: 카메라 복구 3회가 모두 실패해도, 시청자가 계속 기다리는 동안에는 30초마다 다시 시도합니다. 원격 시청자는 Mac의 재시작 메뉴를 누를 수 없기 때문입니다. 움직임 녹화는 이전처럼 오류 상태에서 수동 재시작을 기다립니다.
- 로그인 자동 실행을 켜면 비밀번호 확인 뒤 원격 대기 상태가 됩니다. 녹화까지 자동으로 켜지는 것은 `원격 시청 대기`를 끈 경우와 매일 예약을 쓰는 경우뿐입니다.

## 구조

```text
휴대폰 실시간 화면
  │ 5초마다 POST /api/live/demand (세션·Origin·CSRF 검사)
  ▼
Go 게이트웨이 ── Runtime/live-demand.json 을 원자적으로 교체
  ▼
LiveDemandMonitor (1초 주기) ── 내용이 바뀌면 20초 임대 갱신
  ▼
CaptureModePolicy ── off / live / recording 결정
  ▼
AppDelegate ── LocalMonitoringPipeline.setRecordingEnabled → MonitoringCoordinator.start/stop
```

- 게이트웨이는 별도 프로세스이고 기존 상태 파일과 같은 방식으로 파일로만 앱과 통신합니다. 앱에 새 네트워크 포트를 열지 않습니다.
- 앱은 파일 내용의 변화만 봅니다. 시각 값을 비교하지 않으므로 이전 실행에서 남은 파일이 카메라를 켜지 않고, 벽시계 변경이 카메라를 켜 두거나 끄지 않습니다.
- `live` 모드의 FFmpeg는 RTSP 출력 하나만 가집니다. 감지기와 보관 관리자를 만들지 않으므로 `Spool`과 `Recordings`에 쓰지 않습니다.
- 대기 중에는 `PreventUserIdleSystemSleep` assertion과 App Nap을 막는 activity를 유지합니다. 화면 절전은 허용하므로 접속이 화면을 깨우지 않습니다. 시스템 잠자기 예약이 있는 모드의 휴식 시간에는 예약을 방해하지 않도록 해제합니다.
- HTTPS 설정이 된 앱이 시작될 때 카메라 권한을 미리 요청합니다. 소유자가 Mac 앞에 있을 때 승인해 두어야 원격 시청자가 권한 창에서 막히지 않습니다.

## 함께 고친 결함 — 실시간 영상이 어떤 경우에도 열리지 않음

**현상.** 감시를 켜 두어도 웹이 `실시간 영상을 사용할 수 없습니다`를 표시하고 녹화 탭을 엽니다.

**원인.** 게이트웨이의 `mediaReachable`이 MediaMTX `GET /`의 응답을 200~399일 때만 연결됨으로 판정했습니다. 고정 버전 v1.21.1은 정상 동작 중에도 `/`에 404를 돌려줍니다. 실제 바이너리로 확인했습니다. 기존 테스트는 204를 돌려주는 가짜 서버만 썼기 때문에 드러나지 않았습니다.

**영향.** 원격 실시간 기능 전체가 실제 환경에서 동작하지 않았습니다. 대상 iMac에서 HTTPS를 설정한 적이 없어 지금까지 발견되지 않았습니다.

**수정.** 5xx가 아닌 응답은 서버가 살아 있는 것으로 판정합니다. 스트림 유무는 WHEP 응답으로 판단합니다.

**검증.** `TestRunningMediaMTXRootNotFoundIsReportedAsLiveAvailable`이 수정 전 실패하고 수정 후 통과합니다. 실제 MediaMTX 연동은 아래 종단 검사에서 확인했습니다.

## 한계

- 앱이 실행·인증된 상태여야 합니다. 재부팅이나 로그아웃 후에는 Mac 앞에서 앱 비밀번호를 넣어야 접속할 수 있습니다.
- 수동 잠자기, 전원 차단, 시스템 잠자기 예약 시간에는 접속할 수 없습니다.
- 카메라를 켜는 동안 몇 초가 걸립니다. 실제 iMac에서의 시간은 아직 측정하지 않았습니다.
- 대기 중에는 Mac이 잠들지 않으므로 전력을 계속 사용합니다. 카메라와 인코더는 꺼져 있습니다.
- 로그인한 시청자는 누구나 카메라를 켤 수 있습니다. 표시등을 숨기지 않으며, 메뉴의 `원격 시청 대기`를 끄면 막을 수 있습니다.
- 공인 IP를 공유하는 회선(CGNAT)에서는 중계 서버가 없어 외부 접속이 되지 않습니다. 이 기능으로 해결되지 않습니다.

## 검증

실행한 검사:

- Go 테스트 전체 통과, `go vet`, Darwin/amd64 게이트웨이 교차 빌드. 익명·다른 Origin·잘못된 CSRF의 시청 요청 거부, 거부된 요청이 파일을 쓰지 않음, 요청마다 파일 내용이 바뀜, 새 상태 필드와 잘못된 모드 값 거부를 포함합니다.
- Node 테스트 45개 통과. 9개는 수정 전 실패를 확인했습니다. 보이는 실시간 화면만 시청 요청을 보내는지, 카메라 대기 중 재시도와 화질을 소모하지 않는지, 대기에 시간 제한이 있는지를 포함합니다.
- 실제 브라우저 종단 검사: 실제 게이트웨이(평문 HTTP로 띄운 시험용 빌드), 실제 MediaMTX v1.21.1(Windows), 실제 Chromium WebRTC로 실행했습니다. 앱은 같은 임대 규칙을 쓰는 시험용 대역이고 영상은 브라우저에서 보낸 테스트 패턴입니다. 확인한 결과는 다음과 같습니다.
  - 로그인 직후 녹화 탭으로 넘어가지 않고 `카메라 켜는 중…` 표시, 시청 요청으로 MediaMTX 시작.
  - 약 7초 뒤 640×360, 15fps, 손실 0%로 재생.
  - 녹화 탭으로 옮긴 뒤 마지막 요청에서 정확히 20초 후 카메라 꺼짐.
  - 실시간 탭으로 돌아오면 다시 켜지고 재생.
  - 재생 중 MediaMTX를 강제 종료하면 녹화 탭으로 넘어가지 않고 대기하며, 다시 뜨면 스스로 재연결.
  - 375px 폭에서 가로 넘침 없음. 플레이어 수치 줄이 영상을 가려 좁은 화면에서 숨겼습니다.

실행하지 못한 검사:

- **Swift 소스와 XCTest는 컴파일하지 않았습니다.** Windows에 Swift 도구가 없습니다. 대상 iMac의 `Build MacMonitor.command`가 첫 검사입니다.
- 실제 카메라로의 시작·중지 반복, FFmpeg RTSP 단독 출력, 표준·절약 화질의 필터 시작 시간.
- 화면 꺼짐·잠금 상태에서 **카메라를 새로 시작**하는 동작. 기존 검증은 켜져 있던 카메라가 계속 도는 경우뿐입니다. 이 기능의 가장 큰 미검증 위험입니다.
- 실제 휴대폰, 데이터망, 공유기 NAT, Safari.
