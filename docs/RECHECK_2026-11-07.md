# 2026-11-07 대상 iMac 첫 병합 소스 빌드와 테스트 수정

2026-11-07 릴리즈 `mac-test-20261107-124703`을 대상 iMac에서 `Build MacMonitor.command`로 실행한 결과입니다. 기능 1~6을 포함한 병합 소스가 Mac에서 컴파일된 첫 기록입니다.

## 확인된 사실

- Xcode 14.2 / Swift 5.7에서 소스 전체 컴파일 성공 (`Build complete! 32.67s`). 10-23 재점검이 "다른 SDK 신규 API나 Swift 5.8 이후 문법은 찾지 못했다"고 적은 범위는 76개 파일이었고, 병합으로 들어온 73개 파일에서도 컴파일 오류는 없었다.
- 셸 스크립트 회귀 검사 16개 통과. MediaMTX 1.21.1 내려받기와 체크섬 검증 통과.
- Swift 테스트 76개 중 73개 통과, 3개 실패. 실패는 모두 `RemoteStreamProfilesTests`이며 테스트 결함이다. 빌드 스크립트가 테스트 실패에서 멈춰 Thread Sanitizer, 앱 번들 조립·서명, 실행 전 진단, 앱 실행은 아직 실행되지 않았다.

## 실패 1 — `testProfilesAreOnDemandLoopbackOnlyWithoutRecordingOutputs` (14행)

`paths.contains("127.0.0.1:8554/live")`가 거짓이었다. 프로필 명령은 `JSONEncoder`로 YAML 큰따옴표 스칼라를 만드는데, Darwin Foundation의 `JSONEncoder`는 기본값으로 `/`를 `\/`로 쓴다. 그래서 설정 문자열에는 `127.0.0.1:8554\/live`가 들어간다. 같은 실행에서 고정 MediaMTX 바이너리로 생성 설정을 `--validate-conf`로 검증하는 테스트와 생성 토큰으로 실제 명령을 실행하는 테스트는 통과했으므로 이 형식은 MediaMTX가 받아들인다. 런타임 코드는 그대로 두고, 테스트가 `runOnDemand` 스칼라를 JSON으로 디코딩한 뒤 명령 내용을 검사하도록 바꿨다. Linux Foundation은 `/`를 이스케이프하지 않아 Windows·Linux에서 작성한 테스트가 이 차이를 알 수 없었다.

## 실패 2 — `testExecutablePathControlCharactersAreRejectedForConfigAndEnvironment` (41·42행)

문자 세 개(`\n`, `\r`, NUL) × 단언 두 개 중 두 개만 실패했으므로 한 문자에서만 throw가 없었다. `URL(fileURLWithPath:)`는 C 경로를 기반으로 파일 URL을 만들기 때문에 NUL은 `url.path`에 남지 않고, 검증기는 NUL 없는 경로를 받아 정상 통과한다. `\n`·`\r`는 거부됐다. 런타임의 FFmpeg URL은 번들 경로와 고정 리터럴에서만 만들어지므로 NUL이 도달할 길도 없다. 테스트는 URL이 문자를 보존한 경우 반드시 거부하고, URL 단계에서 이미 떨어진 경우 설정·환경변수 값에 그 문자가 없음을 확인하도록 바꿨다. `docs/FEATURE_6_REMOTE_QUALITY.md`의 "CR/LF/NUL을 포함하는 경로는 거부한다"는 계약은 유지된다.
