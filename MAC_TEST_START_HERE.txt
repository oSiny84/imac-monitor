MacMonitor — Mac에서 처음 테스트하기
====================================

2026-10-20 기능 1~6 수정본에 2026-10-23 빌드 도구·Xcode 14.2 컴파일 수정을 합친 것입니다.
이전 ZIP 대신 새 폴더에 압축 해제해서 사용하세요.
변경·검사 기록: docs/RECHECK_2026-10-20.md, docs/RECHECK_2026-10-23.md
최신 수정 기록: docs/REVIEW_FIXES_2026-10-20.md
2026-10-23 수정: Xcode 선택 확인, Xcode 14의 Swift 버전 출력 파싱, Monterey용 FFmpeg 설치 안내,
Xcode 14.2 SDK 컴파일 오류(.AVCaptureSessionRuntimeError), lipo 인자 순서.
2026-10-20 수정: 너무 작은 감지 영역 거부, 실제 표본 좌표 일치, Safari 뒤로가기 복원,
공백·따옴표·$가 포함된 FFmpeg 경로 처리. Mac 실기 검증은 남아 있습니다.
추가 기능 1: 감시 중지·화면 전용 휴식 중 과거 녹화의 원격 접근 유지.
HTTPS 설정 뒤 추가 테스트: docs/FEATURE_1_ARCHIVE_ACCESS.md
추가 기능 2: 실제 프레임·FPS·녹화·디스크 상태와 프레임 단절 복구.
추가 테스트와 한계: docs/FEATURE_2_MONITORING_HEALTH.md
추가 기능 3: 녹화 날짜 검색·작은 미리보기·원본 MP4 다운로드·페이지 이동.
추가 테스트와 한계: docs/FEATURE_3_RECORDING_BROWSER.md
추가 기능 4: 중요 녹화 보호·해제, 자동 정리 제외, 보호만 보기와 공간 경고.
추가 테스트와 보호 정보 백업 주의: docs/FEATURE_4_RECORDING_PROTECTION.md
추가 기능 5: 감지·제외 영역 편집 (영역 적용 → 설정 저장 → 감시 재시작).
사용 방법과 검사: docs/FEATURE_5_MOTION_REGIONS.md
추가 기능 6: 원격 자동·원본·표준·절약 화질과 수신 통계. 녹화 설정은 유지.
추가 인코딩·재연결·미검증 범위: docs/FEATURE_6_REMOTE_QUALITY.md

releases 폴더에서 날짜·시각이 가장 늦은 ZIP이 이 합본 소스입니다.
그 이전 ZIP에는 기능 1~6과 2026-10-23 빌드 수정 중 한쪽이 빠져 있으니 받지 마세요.

1. 무엇을 옮기나요?
GitHub 저장소의 releases 폴더에서 최신 MacMonitor-Mac-Test-날짜-시간.zip을
클릭한 뒤 Download raw file 버튼으로 받습니다.
Windows에서 직접 옮길 때도 releases 폴더의 ZIP 하나만 옮기면 됩니다.
Mac의 다운로드 또는 문서 폴더에서 압축을 풀고, 나온 MacMonitor 폴더를
통째로 유지하세요. Build MacMonitor.command 파일만 따로 옮기면 안 됩니다.
이 ZIP은 최신 소스와 빌드 도구 모음입니다. 완성된 앱 설치 파일은 아닙니다.
Windows에서 만들어져 있던 dist/MacMonitor.app은 포함하지 않습니다.

2. 최초 한 번 필요한 준비
대상: Intel iMac, macOS Monterey 12.5 이상.
현재 빌드 스크립트는 Xcode 14.2 / Swift 5.7.x, Go 1.26.x,
FFmpeg(h264_videotoolbox 인코더 포함)를 요구합니다.
FFmpeg는 /usr/local/bin/ffmpeg 또는 /opt/homebrew/bin/ffmpeg에서 찾아야 합니다.
Monterey에서는 Homebrew 대신 evermeet.cx/ffmpeg 의 Intel용 ffmpeg ZIP을
받아 /usr/local/bin에 복사하는 방법이 간단합니다. 명령: docs/SETUP_MAC.md
전체 Xcode 및 올바른 Command Line Tools 선택이 필요합니다.
Xcode 14.2는 App Store가 아니라 https://developer.apple.com/download/all/ 에서
Xcode_14.2.xip을 받아 응용 프로그램 폴더에 두고 한 번 실행해 설치를 마칩니다.
그다음 터미널에서 한 번 실행합니다.
  sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
"tool 'xcodebuild' requires Xcode" 오류는 이 선택이 안 된 상태입니다.
이 개발 도구들은 빌드 실행 파일이 자동 설치하지 않습니다.
MediaMTX는 실행 파일이 다운로드하고 검증하므로 인터넷 연결이 필요합니다.
도구 준비가 안 됐다면 먼저 실행해 오류 로그를 보내주세요.
자세한 준비 설명: docs/SETUP_MAC.md

3. 무엇을 실행하나요?
압축을 푼 MacMonitor 폴더 안의 Build MacMonitor.command를 더블클릭합니다.
출처 확인으로 막히면 해당 파일을 우클릭 > 열기로 시도하세요.
보안 설정을 전체 해제하지 마세요. 계속 막히면 오류 화면을 보내주세요.
터미널 창이 열리는 것은 정상입니다. 명령어를 직접 입력할 필요는 없습니다.
자동으로 MediaMTX 준비 → 테스트 → 동시성 검사 → 앱 빌드 → 진단 → 앱 실행을 합니다.
실패 시 멈추며 dist/build-날짜-시간.log에 결과가 남습니다.
성공하면 dist/MacMonitor.app이 생기고 실행됩니다.
다음 실행부터는 그 MacMonitor.app만 더블클릭하면 됩니다.
첫 테스트 동안은 앱이나 소스 폴더를 다른 위치로 옮기지 마세요.

4. 첫 실행 및 기본 녹화
- 12자 이상 앱 비밀번호를 설정합니다. 이후 앱 재실행 때 입력합니다.
- 앱은 메뉴 막대에 표시됩니다. 일반 메인 창이 안 떠도 정상입니다.
- 설정에서 카메라를 선택하고, 처음에는 매일 예약과 로그인 자동 실행을 끕니다.
- 감시 시작을 누르고 macOS 카메라 권한을 승인합니다.
- 카메라 사용 표시등이 켜지는지 확인합니다.
- 움직임 전 보존 30초 / 후 보존 1분을 저장한 뒤 감시를 중지·다시 시작합니다.
- 40초 이상 조용히 둔 뒤 10초 정도 움직이고, 이후 100초 이상 기다립니다.
- Finder > 이동 > 폴더로 이동에서 아래 경로를 붙여넣습니다.
  ~/Library/Application Support/MacMonitor/Recordings/
- 사건 MP4가 생기고 재생되는지, 움직임 전후가 들어 있는지 확인합니다.
- 3분 이상 움직임 없이 두고 새 사건 파일이 계속 쌓이지 않는지 확인합니다.
  임시 버퍼 파일은 정상적으로 만들어졌다 삭제될 수 있습니다.

5. 화면 꺼짐·잠금 중 감시
- 예약을 끈 채 감시를 시작합니다.
- 화면이 자연스럽게 꺼진 상태와 Apple 메뉴의 화면 잠금 상태에서 각각 2분 기다립니다.
- 그동안 카메라 앞에서 움직여 녹화가 계속 되는지 확인합니다.
- 화면을 깨운 뒤 메뉴의 진단 로그 폴더 열기에서 capture-probe.jsonl을 확인합니다.
  화면 꺼짐·잠금 구간에도 frame_heartbeat가 이어져야 합니다.

6. 모드 1: 시스템 잠자기 → 깨운 직후 화면 끄기
이 기능은 시뮬레이션이 아니라 실제 Mac 잠자기와 전원 예약입니다.
- 기존 Mac 전체 전원 예약을 바꿉니다. 확인 창의 기존 예약을 먼저 기록하세요.
- 매일 예약을 켜고 위 모드를 선택합니다.
- 휴식 시작을 지금보다 3분 뒤, 감시 재개를 7분 뒤로 설정하고 저장합니다.
- 관리자 인증 후 앱을 켜둡니다. 앱 종료·로그아웃은 하지 마세요.
- 잠자기 약 1분 전 감시 중단 → 실제 시스템 잠자기 → 예약 깨우기를 확인합니다.
- 깨울 때 키보드·마우스를 건드리지 말고 화면이 약 1초 뒤 다시 꺼지는지 봅니다.
  화면이 잠깐 켜질 수 있습니다. 앱 비밀번호 재입력 없이 감시가 재개되어야 합니다.
- 이후 마우스로 화면을 켰을 때 앱이 반복해서 화면을 끄지 않아야 합니다.

7. 모드 2: 시스템 유지 · 화면만 끄기
- 모드를 변경하고 휴식 시작을 2분 뒤, 감시 재개를 5분 뒤로 설정합니다.
- 모드 1에서 전환하면 이전 시스템 예약 해제를 위한 관리자 인증이 필요합니다.
- 휴식 시각부터 최대 약 10초 안에 감시 중단·화면 꺼짐을 확인합니다.
- 시스템 자체는 깨어 있고, 휴식 동안 카메라·녹화는 중단되어야 합니다.
- 재개 시각에 화면을 켜는 명령 없이 감시가 다시 시작되는지 확인합니다.
- 휴식 중 마우스로 화면을 켠 뒤 30초 기다려 강제로 다시 꺼지지 않는지 확인합니다.
- 모드 2는 수동 잠자기나 전원 차단을 막거나 별도 예약 깨우기를 하지 않습니다.

8. 테스트 종료
- 매일 예약을 끄고 저장합니다. 시스템 예약 해제 확인이 나오면 확인합니다.
- 테스트 전에 다른 전원 예약이 있었다면 기록해 둔 내용으로 복원해야 합니다.
- 감시 중지 후 앱을 종료합니다.
- 앱 종료만으로 모드 1의 시스템 전원 예약이 지워지지는 않습니다.
- 앱 재실행 시 비밀번호를 다시 요구하는지도 확인합니다.
- 완전히 지우려면 폴더 안의 Uninstall MacMonitor.command를 더블클릭합니다.
  앱·자동 실행·비밀번호·설정·카메라 권한을 지우고 녹화는 남깁니다.
  Mac 전체 전원 예약은 따로 한 번 더 물어본 뒤에만 해제합니다.
  소스 폴더는 남으므로 끝난 뒤 직접 휴지통으로 옮기세요.

9. 결과로 무엇을 보내나요?
- iMac 모델, macOS 버전, 성공/실패한 위 단계 번호와 발생 시각.
- 실패 화면 캡처와 압축을 푼 폴더의 dist/build-날짜-시간.log.
- 실행 중 문제라면 앱 메뉴 > 진단 로그 폴더 열기의 해당 시각 로그.
  capture-probe.jsonl / ffmpeg.log / mediamtx.log / gateway.log
- 비밀번호, 인증서 개인 키, 녹화 영상은 보내지 않아도 됩니다.
  로그에 공개 IP·도메인·사용자 경로가 있으면 필요에 따라 가려주세요.

첫 테스트에는 외부 접속 설정이나 포트포워딩이 필요 없습니다.
휴대폰 원격 시청은 별도로 HTTPS 인증서·웹 비밀번호·공유기 설정 후 테스트합니다.
자세한 전체 검증: docs/MAC_VALIDATION.md (예약 모드는 J와 K)

현재 상태: Windows에서 소스/스크립트를 점검했으며,
Swift 빌드와 실제 카메라·전원 동작은 대상 Mac에서 아직 검증하지 않았습니다.
